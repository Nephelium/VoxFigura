## 舞台人声、目录和连续语音

- [x] 核对 F 盘关键帧预览实现与项目内 `Tract2Vox-Lite` 权重。工作台接入 50 Hz 全维预测并保留手工控制。用两条旧版网页合成请求原样复算，分别生成 359 和 103 帧构音轨，前后时长分别保持 344,348 和 98,448 个采样。
- [ ] 井井试听同音色、同 F0 的《茉莉花》和「春江潮水连海平」，判断字间衔接和电音感。四个 WAV 在 [连贯合成对照](试听/连贯合成对照/)。
- [x] 只有音素的 A1 在没有 WAV 或 MIDI 音符时可以合成播放。单独 A1、单独伴奏、混合播放、暂停续播及改参数后重算均已实测。MP4/AAC 与 WebM/Opus 解码后同时检出人声与伴奏。
- [x] 编曲可独立试听人声和预览有声视频，预览以 WAV 为时钟，关闭后保留舞台播放头和片段。发送到 A1 后自动试听送入的片段，正式导出在舞台。1707 与 1450 CSS 像素两种宽度下工具栏按钮均无交叠。
- [x] 左上角仅保留标记。Edge 在 150% 显示缩放下打开本地文件夹，核对目录占满媒体库、搜索与返回上级目录，拖入 PNG 后 V2 出现对应片段，关闭目录后恢复项目素材。

用空白浏览器配置打开 JD2 编曲，合成音源默认选择 `Tract2Vox-Lite`。已有配置明确选择 VTL 时仍使用物理合成。另测原生目录句柄，可进入空子目录，单独导入文件后切回项目素材。

同输入对照中，「春江潮水连海平」各音素边界附近的声道跳变量中位数由 0.097 降至 0.038，《茉莉花》由 0.122 降至 0.023。计算时将 17 个声道参数分别按模型范围归一化，在每条边界附近取相邻帧差的最大均方根，再跨边界取中位数。「春江潮水连海平」最突兀的一处由 0.148 升至 0.162，仍值得回听。新空白工程另经编译、细分塞音相位和整句合成，结果见 [当前标注页实际输出](试听/连贯合成对照/春江潮水连海平·当前标注页.wav)。

编曲预览和发送到舞台的同一片段产生完全相同的 WAV，V1 收到的 71 帧姿态与合成回传逐值一致。另用 2.051 秒的普通话句子验证 A1 与 V1 的 103 个控制帧。实际声码器测试使用本地 CPU，CUDA 检查覆盖请求路由和故障反馈。

[舞台混音测试片段](试听/连贯合成对照/舞台·人声与伴奏.mp4) 为 1 秒 1080p MP4。伴奏轨特意使用 425 Hz 参考音，便于解码后分别检测两条轨道。判断合成人声的听感请使用上方干声 WAV。

## 三份架构文档和当前实现的差异

- 早期架构把普通话、英语韵律与对齐写成预留接口。本机的正式 Lite 权重已到位，两条路径均改为使用项目内推理。设置的「声学引擎」逐项查询权重文件是否在本机，实际合成以试听请求验证。
- 早期设计的六种发声态无法覆盖实录 VoQS。工作台改用录音条目；升喉、降喉另存喉位控制。专用发声态过渡权重仍需后续核对，锚点沿用到下一个显式变更。
- 公开版与参赛版共享声道、剪辑及本地 Python 引擎。每次运行一个版本只需该版本的网页入口和代理，两个端口用于本机并列检查两种成品。赛事构建独立增加知乎路由和素材。
