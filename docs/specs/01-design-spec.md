## 1. 产品定位、核心原则与分期准入规则

### 1.1 一句话定位

VoxFigura 是一个把知乎发音问答编译成看得见、听得着、拖得动的物理声道实验的知识探索与剪辑工作台：声音由一条逐帧可调、可溯源的声道与声源轨迹生成。第一层「知乎发音探索实验室」服务于知乎问答科普与跨语对比回流；第二层「科研工作台」与「剪辑工作室」以语音学标注为时间轴主锚点，服务于实验语音学研究与声道演唱创作。

### 1.2 五条不可动摇的设计原则

1. **过程透明，拒绝黑箱**：界面呈现的声道形状、基频曲线、气压包络和声学图必须直接对应底层参数与计算结果。任何可听变化都要在视觉上有明确出处。
2. **TextGrid 是时间轴的一等公民**：音节、音段与音符边界构成全局时间主锚点。声道关键帧、基频靶点、气压包络默认挂载在锚点区间的局部坐标上，拖动边界可无损重算，回到原位可完全复原。
3. **统一命令总线与确定性撤销**：不论修改来自鼠标拖拽、键盘操作、第三方插件、脚本导入还是 AI 工具调用，都必须经过同一条命令总线，支持可审阅预演和一步无损撤销。
4. **科研可信度优先于视觉修饰**：必须严格区分模型计算量与实测声学量、物理合成音与神经声码器音、声道重建候选轨迹与真实器官运动。严禁为界面美观编造参数名或模糊科学含义。
5. **无界面优先与原生 AI 友好（Headless-First & AI-Native）**：所有工程编译、构音微调、抢拍调度、声学诊断、画面抽帧与视频导出能力必须独立于界面层存在。图形界面、内置 AI 对话、未来 CLI 命令行与外部 MCP 客户端平等调用同一套核心命令，确保 AI 能端到端编排完整工作流且第三方插件接入后可立即被 AI 调用。

### 1.3 终局立纲与分期准入规则

本规范面向产品终局架构制定，但所有功能模块和界面入口都必须按交付阶段严格标记并执行露与藏策略：

| 分期标记 | 适用阶段 | 界面展示与实现要求 |
| --- | --- | --- |
| `[MVP-P0]` | 黑客松首版必交闭环 | 必须完整实现、走通命令总线并通过自动化验收测试 |
| `[P1]` | 黑客松冲刺加分项 | 完成则开放入口，未完成时按隐藏规则处理 |
| `[P2]` | 赛后迭代与模型扩展 | 仅在架构、数据结构与设置槽位中预留干净接口，首版界面不暴露死入口 |

**界面露与藏硬规矩**：
- **禁止**在 MVP 界面中放置点击无响应的空壳按钮、假进度条或写死的演示假数据。
- 未到期的独立子视图（如 `[P2]` 阶段的方言包工作室）在首版导航栏中默认隐藏，或在开启实验开关后才以只读规划态出现。
- 需要为后续神经模型预留的控制项（详见第 4 章），默认收纳在折叠区或引擎下拉选择器中，未接入后端时清晰标注“未安装/待接入”并保持主路径可用。

## 2. 全局信息架构、前端本地计算与工作区切分

应用采用三层空间结构：**全局固定顶栏 → 三大互通主工作区切换 → 混合式子视图与联动浮层**。

### 2.1 全局固定顶栏（所有视图常驻）

顶栏高度保持紧凑（标准桌面基准下 46 px，采用三列对称网格确保工作区切换严格居中），由左至右分为三段：
- **左侧**：软件标识 + 当前工作区徽标。
- **中央**：主工作区切换胶囊（严格水平居中），包含三个互通工作区：**知乎发音探索**（Web 版默认首屏）、**科研工作台** 与 **剪辑工作室**（双区均移除冗余的左上角 `[语音 | 歌唱]` 模式开关，以科研精修与舞台编曲自然分工，共享同一份 `.vcproj` 状态）。
- **右侧**：克制聚焦的全局工具区——全局撤销、**使用说明**（占位预留页面）、**AI 助手**抽屉开关（刘看山 × 知乎直答双形态，默认 `zhida-thinking-1p5`）、明暗主题一键翻转、**设置**入口（全宽 7 分区独立页面）、**关于**入口（内收 6 章节「模型训练与技术报告」与 69 条「引用致谢」弹窗）。主题/背景下拉不再堆叠在顶栏，全局「导出」拆分为三大工作区各自上下文专属导出。

### 2.2 三工作区职责切分与前后端计算边界

三大工作区共享同一份底层工程状态（`.vcproj`，拖入任一工程资产框即可双向同步渲染到科研时间轴与剪辑轨道）、同一根播放头、同一条命令总线和同一个撤销栈。全局切换由顶栏统一承担，探索页不再保留重复的科研/剪辑跳转按钮。

**前后端计算边界铁律**：
- **前端（Vue 3 + TypeScript + Vite）全本地计算**：VTL 2.4 Wasm 物理合成、四语文本转 IPA、辅音抢拍调度、qTA 基频、TextGrid 锚定重算、声道 SVG/Canvas 渲染、`<=1080p` 视频解码与 WebCodecs 卡片/视频导出全部运行在用户浏览器本地；赛后轻量化神经模型通过 ONNX Runtime Web 下放用户设备，并在科研工作台、声道重建、连续统、剪辑工作室、导出弹窗与设置页统一提供同步的 `WebGPU 独显优先` / `WebGPU 核显省电` / `本地 CUDA 原生桥接` / `WASM CPU 多线程` 设备选择器。
- **浏览器端短视频性能与 1080p 上限边界**：现代浏览器硬件解码可流畅驱动 **1–2 路 `<=1080p` 短视频片段**；未降采样的 4K 多流高频拖拽会引发主线程掉帧与 GPU 纹理显存过载。因此舞台 `V0` 视频背景上限锁定 **`1920×1080`（1080p）**，超出时自动等比降采样至 1080p 内，交互拖拽擦洗采用轻量 `720p` scrub 代理提示。
- **后端（无数据库极薄 Node 代理）**：仅负责保存服务端密钥（严禁进前端）、绕过 CORS 调用知乎开放平台 REST 接口并做按词/URL 缓存（抗限流与静默随机过滤），以及维护**双通道 AI 路由**（Channel A 接知乎直答 `/v1/chat/completions` 用于科普与知乎语境搜索摘要；Channel B 接支持 `tools[]` 与多模态 `image_url` 的 OpenAI 兼容执行大模型）与 P1 可选重型 TensorTract3 云端 GPU 推理转发，无数据库写入。

**关于科研与剪辑双区的协同规则**：
- 科研与剪辑不再保留冗余左上角 `[语音 | 歌唱]` 模式开关，底层共用同一套音节、音素与靶点 `.vcproj` 结构。
- 在**科研工作台**中，默认服务实验语音学与构音研究（双层 TextGrid、文本/IPA 直合、音素边界拖拽、M27 声道重建与连续统/方言包），也同样支持载入与精修歌唱 `.vcproj`。
- 在**剪辑工作室**中，默认服务歌唱与科普视觉成片（PR 多轨剪辑、直接拖拽舞台、`V0 <=1080p` 视频背景、双行逐字显现 IPA 字幕与 `编曲` 逐字多音简谱定音）。

### 3.2 浏览器与桌面双端覆盖及全屏极紧凑密度

- **双端一致**：规范同时约束 **Web Wasm 桌面浏览器版**（优先交付）与 **桌面原生壳版本**。核心界面代码单一来源，差异仅限于文件读写、视频封装与本地重型任务桥接。
- **分辨率适配与跨屏等效密度**：
  - 默认以 **2560×1600** 物理/高分屏密度作为 `100%`（`--page-scale: 1.00`）视觉基准（依据 `screen.width * devicePixelRatio` 判定物理宽度，高于 `2048px` 时不二次缩放）。
  - 检测到 **1920×1080（`physW <= 2048 && vw <= 1960`）** 时，自动启用 **`86%`（`--page-scale: 0.86`）** 全局缩放，映射出约 `2233×1256` 逻辑画布空间，使字号、面板边距与倒角观感对齐 `2560×1600` 笔记本屏幕效果（并可于设置页手动微调或一键恢复自动）。
  - 向下兼容至 **1366×768（`vw < 1560`）**，自动切换 **`80%`（`--page-scale: 0.80`）** 并收起次要折叠组，禁止出现核心按钮溢出或双层横向滚动条。
  - 暂不做手机端或窄竖屏适配，窄于 1100 px 时给出提示并允许查看只读演示。
- **极紧凑桌面工作站密度与克制倒角（硬性要求）**：
  - 界面字号与控件密度必须明显高于常规网页与 AI 概念预览图，向专业音频/视频工作站（如 DaVinci Resolve、VS Code、原 PhoneticToolbox 专业模块）看齐。

## 4. 面向未来模型与社区生态的两层扩展架构

VoxFigura 既要平滑承接正在训练的 TensorTract3 全声门 27 维声道动态轨迹重建模型、关键帧转动态声道轨迹神经插值模型与可选神经重合成声码器，也要支持社区开发者和研究者以低门槛安全扩展新模板、新方言、新视觉效果与新 AI 技能。

为避免插件失控污染主程序或导致工程不兼容，扩展系统采用**两层受控架构**，并严禁插件绕过命令总线或直接侵入修改主界面 DOM。

### 4.1 第一层：零代码内容插件（纯声明式数据包） `[MVP-P0 构型与模板雏形 / P2 完整包生态]`

社区创作者与语言学者无需编写程序代码，仅通过带版本与校验和的纯数据文件（JSON / Markdown / 静态资源）即可扩展以下五类能力：
1. **构型包（`.vcpack`）**：自定义说话人或个人校准的 IPA 构型集合与参考录音绑定。
2. **方言包（`.vcdialect`）**：转写映射表、调类表、连读变调规则与录音拟合调值。
3. **MV 场景与字幕模板（`.vctpl`）**：预设舞台构图、节拍脉冲绑定、配色样式与双行 IPA 字幕版式，供 AI 或用户一键套用。
4. **发音卡片版式包**：面向不同社区与课件规格的 1:1 / 9:16 卡片排版模板。
5. **AI 工作流剧本（Playbook / Skill）**：针对特定创作或科研任务的纯文本步骤手册（如特定戏曲唱腔调教、特定方言对比实验），加载后可被 AI 按需读取。

### 4.2 第二层：受控功能插槽（含三大可替换声学/神经模型环节） `[MVP-P0 契约预留 / P2 插件加载]`

代码级扩展必须通过统一插件清单（`PluginManifest`）向固定能力插槽注册，核心包含以下两类插槽：

#### A. 生成模型强制基线、三大可替换模型插槽与第三方可移植打包契约

1. **生成模型强制基线（禁止自造简化声道或虚假合成器）**：
   - 正式工程中所有**音频与物理状态生成**必须采用 `PhoneticToolbox_v3`（`D:\PhoneticToolbox\PhoneticToolbox_v3`）真实 `VTL 2.4` M10 引擎内核（复用说话人 `JD2` / `W02` XML 声门预设、`flutter` 慢速漂移与 seeded `shimmer`，停用旧版 `voiced`/`voiceless`/`whisper` 及 Schoentgen jitter）；
   - 正式工程中所有**二维正中矢状面与三维头颈声道几何可视化**必须复用或严格同构衔接 `PhoneticToolbox_v3` 于 `2026-11-20` 重做验收的新版二维/三维模型（`frontend/public/vocal-tract/embed.mjs`，含 `TONGUE_FOLLOW` 联动、`head-model.mjs` / `face-model.mjs` / `jd2-jaw.mjs`）；静态 HTML 原型阶段的轻量矢量图仅作版面占位。
2. **三类模型零 UI 耦合打包（方便任意第三方项目直接集成复用）**：无论是**二维声道模型**、**三维声道模型**还是**自训神经网络模型**，均严禁把权重、前后处理或渲染逻辑写死在 Vue 界面组件中，必须输出以下四组零框架耦合、可被第三方科研/Web/桌面项目直接复制接入的独立模块包（配最小可运行示例与声明式清单 `manifest.json`）：
   - **二维/三维可视化独立包（复用 `embed.mjs` 标准）**：暴露无状态渲染契约 `mountVocalTract(el, { metadata, state, view: 'sagittal' | 'model', pose, options, theme, locale, linkLips, onChange, onSelect })` 与 `update(state)` / `snapshot(view)` / `setView` / `undo` / `redo`；仅渲染 `sagittal` 时零 WebGL 依赖，切换 `'model'` 即可在任意 HTML / Qt / WebView2 / Electron 宿主跑通完整 3D 头颈切面与 `#fullModelToggle`。
   - **物理声学与调度计算包（`vocalcut_core` / VTL Wasm Adapter）**：独立于 DOM，接收标准化帧与密集 `f0_hz[]` / `pressure_pa[]`（含非钢琴纯 IPA 手绘连续音强曲线与 `±120 Pa` 强弱偏移）并返回 48 kHz PCM 及几何状态。
   - **自训神经模型包（`TensorTract3` 等训练产物）**：以独立推理模块 + 标准化权重（`.onnx` / `.pt`）+ `model.manifest.json`（声明 `16 kHz` 输入、`50 Hz 27D m27 + pressure_pa + f0_hz` 输出、WebGPU/CUDA/CPU 执行后端与许可）交付，外部系统可绕过 VocalCut UI 直接调用。

#### B. 整条“录音/音标 ↔ 声道轨迹 ↔ 波形”三大可替换插槽

```text
[输入：真人录音] ──▶ (插槽一：声道重建引擎) ──┐
                                              ▼
[输入：文本/IPA/关键帧] ──▶ (插槽二：轨迹过渡引擎) ──▶ 统一时间轴动态轨迹（关键帧层 + 手绘 F0/PS + 离散发声态）
                                                                       │
                                                                       ▼
                                                        (插槽三：声学发声引擎) ──▶ 音频波形与声学图
```

1. **插槽一：声道重建引擎（录音 → 声道与声门轨迹）**
   - 可切换后端：`TensorTract3`（`F:\TensorTract3_Train`）云端极薄 API `[P1]` → 赛后双轻量本地 ONNX 模型（极轻浏览器版 / 高精度桌面版，用户可于界面直接切换 WebGPU 独显 / 核显 / 本地 CUDA / WASM CPU）`[P2]`；旧版 Viterbi 候选库作为离线兜底。
   - 维度平滑承接：现有构型为 19/20 维，在训的 `train_m27_pipeline.py` 已扩展至 **27 维全声门控制（`m27`）**加肺压与基频。右侧声源与时间轴 `PHON` 轨采用两层渐进披露——常规层采用 **6 档离散发声态锚点**（`挤压 / 常态 / 气声 / 耳语 / 嘎裂 / 假声`，直连两端 `m27` 参数插值），高级全声门层默认折叠并完整承接 `m27` 细粒度参数。
2. **插槽二：轨迹过渡与插值引擎（IPA 关键帧 + 事件地标 → 动态声道轨迹）**
   - 可切换后端：`PhoneticToolbox_v3` 规则物理插值基线 `[MVP-P0]`（后续升级为带器官自由度掩码的多轨异步二阶目标逼近 + 路径级几何护栏）→ 物理基线 $x_{\text{base}}(t)$ 加轻量神经残差模型 $\Delta x(t)$ `[P2]`。
   - 界面零破坏预留：① 在国际音标表 Plus 构型编辑器与关键帧属性栏中，为各器官组（唇部、下颌、舌尖、舌叶、舌背、舌根、软腭）预留默认折叠的**器官约束权重开关**（`强约束 1.0` / `自动借位` / `自由 0.0`），默认按 IPA 部位方式自动套用模板；② 底层时间轴轨支持关键帧基准加细节修正叠加，`F0` 轨支持 `靶点 / 钉住 / 颤音 / 微扰 / 自由手绘`，**`PS` 气压（音强）轨支持在纯 IPA 非钢琴合成下自由手绘连续包络**；③ 闭塞起点、除阻时刻与 VOT 始终作为显式事件地标保留在时间轴上，任何插值后端都必须尊重用户对地标的微调。
3. **插槽三：声学发声引擎（动态声道轨迹 → 音频波形）**
   - 可切换通道：默认基准为 `PhoneticToolbox_v3` 封装的 VocalTractLab 2.4 **物理管段通道** `[MVP-P0]`；赛后可选挂载轻量 **Neural Re-synthesis 神经声码器通道** `[P2]`。
   - 来源标注铁律：一旦切换至神经重合成通道，界面预览徽章、波形标签与导出元数据必须明确标注“神经声码器渲染”，且实时面积函数与模型共振峰仍注明来自物理声道模型，禁止与物理管段输出混为一谈。

#### B. 创作与工具扩展插槽 `[P2]`

- **视觉图层渲染器插槽**：允许注册新的确定性画面图层（如自定义频谱样式、粒子特效、舞台滤镜），输入仅限当前帧号、音频特征与确定性随机种子，必须满足预览与导出同源一致；若含背景视频流则统一受 `<=1080p` 上限约束。
- **格式编解码插槽**：允许扩展新的乐谱、标注或科研数据导入导出格式。
- **自定义语义工具插槽**：允许注册复合业务命令（如批量声调转换、自定义风格化剪辑宏），必须提供参数 JSON Schema、权限分级（`R` / `E` / `X`）与逆向撤销补丁逻辑。

### 4.3 插件向 AI 自动暴露原则

- 所有通过 `PluginManifest` 注册的语义工具与模板元数据必须自动汇入系统的统一「命令与工具登记表」。
- 登记完成后，内置 AI 对话与外部 MCP/CLI 客户端立即能够发现并调用该插件能力，无需修改主程序或重写系统提示词，真正实现“安装一个扩展，AI 自动获得一项新技能”。
- 第三方插件声明的权限级别必须经系统强制校验，凡涉及编辑工程状态的均走提案审阅事务，凡涉及文件系统或联网副作用的均强制经用户二次确认。

- **时间轴五项核心交互硬规**：
  1. **离散发声态锚点入轨**：`PHON` 作为独立轨道进入时间轴，沿时间对齐音素边界显示 6 档离散泳道与锚点折线，支持增删锚点并直接插值 `m27` 声门参数，拖动仍强制吸附档位。
  2. **各轨独立调高与单轨放大微调**：时间轴内**每一条轨道底部均提供独立高度拖拽条**；`F0 控制基频` 与 `PHON 离散发声态锚点` 两条高密编辑轨另配「单轨放大微调」切换，可单独扩高至大画布进行高精度捏点与曲线描摹，其余轨道自动避让并保持整区竖向可滚。
  3. **`F0` 与 `PS` 双轨自由手绘（含非钢琴 IPA 音强手绘）**：`F0 控制基频` 除 qTA 靶点与音素微调外，支持一键切换「手绘基频」直接描画连续 `F0`；**当纯国际音标语音合成不使用钢琴/简谱定音时，在 `PS 声门下压 (Pa)` 轨同样支持一键开启「手绘音强」直接鼠标描画 `0–1600 Pa` 连续强弱起伏包络**，绕开旧 201 点限制直出密集 `f0_hz[]` / `pressure_pa[]` 控制数组。
  4. **横向拖选多音素与长时序横向滚动缩放**：按住拖拽可在时间轴上一次**横向框选/拖选多个连续音素**；长时序音频或长句**严禁挤压所有音素强行塞进单屏宽度**，必须保持最小可读音素宽度并启用真正的横向滚动条、水平缩放（`Ctrl + 滚轮` / 工具条滑块）与轨道竖向滚动。
  5. **`TextGrid 音节层` 直点交互与右下角小三角切音**：在 `TextGrid 音节层` 区块内，多音字在区块**右下角渲染一枚高对比小三角标记**；仅当用户点击该**右下角小三角**时弹出多音字读音切换浮层并更新其下挂音素序列，**点击音节块其余任意区域一律仅执行「选中该音节区域」**，杜绝误切换读音。
- **既有联动规则**：
  - **边界拖拽实时同步 `[P1]`**：左右拖动 TextGrid 音素边界句柄时，相邻音素时长按毫秒实时重算，并**同步伸缩 `PHON`、`F0` 靶点与 `PS (Pa)` 包络曲线**；若压缩至低于塞音闭塞刚性下限时阻挡并弹出可读提示。

## 6. AI 原生全流程控制、视觉审片与安全规范 `[MVP-P0 核心 / P2 外部 MCP 与全自动长流程]`

AI 助手及外部接入 Agent 均作为受控的编排与精修代理，通过无界面内核与统一命令总线操作工程，既支持定点参数微调，也支持端到端包揽整套声道视频制作流程。严禁任何 AI 路径绕过命令总线直接改写工程或产出不可复现音频。

### 6.1 知乎直答与执行模型双通道 AI 路由、权限隔离及安全红线 `[MVP-P0]`

1. **已核实的知乎直答接口边界、实时配额与双通道 AI 路由**：
   - 经 `2026-11-22` 实调免费端点 `GET /api/v1/quota` 与官方 `http-api.md`/`oauth.md` 核实：`POST /v1/chat/completions`（`zhida-fast-1p5`、`zhida-thinking-1p5`、`zhida-agent`）只接受 `Authorization: Bearer <access_secret>` 与 `X-Request-Timestamp`（不接收 OAuth token，仅保证 `model / messages / stream` 生效，`zhida-agent` 仅单轮上下文）；实测账号免费额度为 **`zhida_openai` 直答 `100 次/天`**、**`question_discovery` 问题发现（含 `question_recommendations` 与 `question_answers`）`100 次/天`**、`zhihu_search` `5,000 次/天`、`creator` `500 次/天`（限频或耗尽返 `30001`）。因此探索页优先走 `zhihu_search` 并对 `question_answers` 与直答按问题/问句强缓存，同时在设置页开放**可选「自带知乎 Access Secret（BYOK）」**，代理层仅 HTTPS 单次透传、严禁落盘和打日志，既提供个人独立额度又支持答主用 `content_detail` 拉取本人原答制卡。
   - 因此系统严格划分**双通道 AI 路由**：**Channel A（知乎直答通道）**负责知乎语境搜索摘要、刘看山语音科普答疑，以及在启用调音建议时通过受控系统提示输出严格 Schema JSON 提案块兜底解析；**Channel B（OpenAI 兼容 `tools[]` 与多模态执行通道，支持用户自配 Key）**接入通用推理/视觉模型，承担高精度函数调用、多步自动化编排与接触表视觉审片。两条通道的所有参数修改均须经过同一条命令总线与范围校验。
2. **三级权限隔离**：
   - `R` 只读工具（工程查询、声学测量、视觉抽帧、构图检查、规则查询、知乎检索）：允许自动调用，界面以低调紧凑折叠条展示调用轨迹。
   - `E` 编辑工具（读谱铺轨、改构型、改基频、改气声、套视觉模板、编排图层关键帧）：必须在工程副本上生成**可审阅提案**，经用户显式点击“接受”才合并进主工程。
   - `X` 外部副作用工具（导出成品文件、删除素材、外部写入）：每次执行前必须弹窗获得用户确认。
3. **提案审阅卡片强制五要素**：每一张 AI 编辑提案卡片必须完整包含——① 结构化参数变更表（改前 → 改后，带单位）；② `analysis.measure` / 构型检查 / 构图检查的前后对比；③ **改前 A / 改后 B / 盲听**试听按钮（涉及视觉改动时附改前/改后关键帧缩略图对比）；④ 清晰的「接受提案」与「拒绝」按钮；⑤ 接受后无论包含多少条子命令，整体作为撤销栈中的一步可一键还原。
4. **不静默夹紧**：AI 传入越界参数（如超出 60–600 Hz 或解剖范围）时，命令层必须直接拒绝并返回合法区间与建议值，由模型自行修正。
5. **内容即数据**：歌词、TextGrid 标签、外部文档、插件说明文本以及 `content_detail` / `question_answers` 返回的知乎正文和摘要一律视作纯数据展示（附来源链接），其中任何指令性语句都禁止触发工具调用。
6. **无网与配额耗尽保底**：内置可明确标识的「回放模式」，在断网、缺少大模型密钥或知乎直答达到日配额上限（错误码 `30001`）时自动缓存降级，仍可完整回放核心演示指令与提案审阅流程，界面须清晰标出状态提示。

### 6.2 AI 感官体系：视觉审片与声学数值诊断（不依赖原生听音频）

本架构**不要求**外接大模型具备原生听音频能力，听感裁决始终交由用户的 A/B 试听完成；系统为 AI 提供高精度的**数值体检**与**可视化图像感官**，确保任何支持看图的主流外接模型都能准确自检成片质量：

1. **视觉审片只读工具（让 AI 亲眼看见成片画面）** `[P1 抽帧 / P2 完整审片]`：
   - `preview.contact_sheet(range, count=6~9)`：在指定范围内自动抓取句首、辅音抢拍点、立绘切换点、字幕最满帧等关键时刻，拼成一张带时间戳与安全边距参考线的 **6–9 格高清接触表**，以极低 Token 成本让 AI 检查构图、配色与遮挡。
   - `preview.snapshot(at, grid=true)`：按需导出单个时刻的高清帧，并可选叠加淡淡的像素坐标标尺与图层边界框，让 AI 精确计算位移与缩放调整量，告别盲猜微调。
   - `layout.lint(range)`：纯程序化检查字幕是否越出安全边距、IPA 是否有缺字、立绘或贴纸是否遮挡核心声道区域，直接返回带帧号与像素偏移的结构化告警。
2. **声学诊断感官（纯文本与看图模型双适配）** `[MVP-P0 数值 / P1 诊断图]`：
   - 结构化体检 `analysis.measure` 与 `analysis.lint`：汇报实测元音踩拍偏差（ms）、F0 音分误差、口腔最小截面积轨迹、闭塞完整性与气声谱倾斜（H1-H2）。
   - 声学诊断复合图 `analysis.plot_diagnostic(range)`：当所选模型支持看图时，可一键渲染四轨对齐诊断图（宽带语谱图叠共振峰 + 目标与实测 F0 曲线 + 最小截面积与塞音爆破标记 + 拍线与 TextGrid），让视觉模型直接读图辅助诊断咬字与韵律问题。
3. **三种面向外接 AI 的标准传图通道**：
   - 外部 MCP Server 出口 `[P2]`：通过 MCP 协议原生 `image` 载荷直接回传 PNG/JPEG；
   - 内置 OpenAI 兼容对话接口 `[P1]`：工具生成截图后自动附加为下一轮推理的多模态 `image_url` 输入（纯文本模型自动降级仅读取 `layout.lint` 与 `analysis.measure`）；
   - 桌面端与 CLI 出口 `[P2]`：将抽帧图写入工程缓存目录（如 `.cache/inspect/`）并在工具返回值中提供明确文件路径，供外部本地编程 Agent 直接读取看图。

### 6.3 全流程编排、分阶段检查点与异步任务句柄

为支持用户一句话委托 AI 完成“读谱定音 → 精修演唱 → 排舞台剪视频 → 导出成片”等长流程任务，必须遵循两项编排规范：

1. **分阶段检查点（Milestone Checkpoints）**：涉及多类轨道的大任务禁止闷头连续执行数十步不反馈，必须划分为清晰里程碑——**① 读谱定音与抢拍铺轨 → ② 咬字与声道精修 → ③ 舞台排版、字幕布局与接触表审片 → ④ 导出成片**。每个里程碑产出独立的阶段摘要、自检结果与可整体撤销的提案，支持用户选择“逐阶段停顿确认”或“授权全自动连续推进（遇校验告警自动暂停）”。
2. **异步任务句柄（Async Job Model）**：整段音频合成、声道动态轨迹重建、批量连续统生成与 1080p 视频导出等耗时操作统一抽象为异步任务，发起调用立即返回 `job_id` 与预估进度，支持轮询状态、取消任务与复用内容摘要缓存，严禁阻塞 AI 对话通道或冻结界面主线程。

### 6.4 两层动态 AI 说明书机制（零过时、低上下文占用）

严禁人工维护一整本与代码割裂的静态巨型《AI 使用手册》，给内置与外部 AI 阅读的指导文档必须采用两层动态架构：

1. **自动生成层（单一真相源）**：所有工具名称、参数 Schema、单位、合法取值范围、错误恢复提示以及插件扩展能力统一由「命令与工具登记表」在构建或加载插件时自动生成，并同步提供给内置工具定义、`rules.get(topic)`、CLI 帮助文档及外部 Agent 可直接加载的 `SKILL.md` / MCP Schema。
2. **按需加载剧本层（Playbooks）**：仅人工维护少量精炼的标准任务剧本（如《声道演唱 MV 制作流程》《咬字与气声诊断精修指南》《生理连续统批处理流程》《发音卡片制作指南》），每篇聚焦步骤顺序、自检红线与验收条件。默认仅在系统提示中放入剧本索引目录，AI 收到对应任务后再按需读取全文，不挤压日常对话上下文。

## 8. 真实声学口径与科研可信度铁律

所有参与界面开发、参数绑定与文案撰写的 Agent 必须严格遵守以下声学事实口径，**严禁自造参数名、错误单位或模糊表述**。

### 8.1 声道参数与坐标真相表（基线：VTL 2.4 与 `PhoneticToolbox_v3`）

| 模块 | 必须遵守的真实口径 | 常见错误反模式（严禁出现） |
| --- | --- | --- |
| 声道核心参数命名 | 使用 VTL 真实命名：下颌 `JA`（及 `JX`）、唇前突 `LP`、唇开度 `LD`、唇宽（独立参数）、舌背 `TCX / TCY`、舌叶 `TBX / TBY`、舌尖 `TTX / TTY`、舌根 `TRX / TRY`、喉位/舌骨 `HX / HY`、腭咽口 `VO`、舌侧缘 `TS1–TS3` | 编造“舌体形状 α”“舌尖位置 11.20 cm”等非 VTL 参数 |
| 声源参数扩展口径 | 6 档纵向对齐离散音质定位点曲线（`挤压 / 常态 / 气声 / 耳语 / 嘎裂 / 假声`，支持自定义增删点、直接两点插值 `m27` 10 维声门参数）+ 可折叠 10 维/27 维全声门细项（兼容 `m27`）+ 肺压（界面单位与图表坐标轴一律换算为 `Pa`，严禁暴露引擎内部 `dPa`） | 混用 `dPa` 与 `Pa`、把离散声门档位拖到档位中间悬浮或伪造连续过渡假象 |

| 物理量与示意量区分 | 面积函数、传递函数共振、控制基频、声门下压包络、最小截面积狭窄高亮为**计算量**；在原生桥接层补齐前，口腔内气流箭头与腔内压力分布仅允许标为**示意（非计算值）** | 把装饰性气流箭头标成真实 CFD 流体计算结果 |

### 8.2 必须严格区分的六组科研表述

在图例、悬停提示、导出弹窗与可复现清单（`manifest.json` / `.card.json`）中，必须始终保留以下区分：
1. **控制基频（`F0_ctl`）** ≠ 实测输出音频基频（且含 flutter 微扰的声源基频记作 `F0_eff`）。
2. **模型传递函数共振峰值** ≠ 对合成音频做 LPC 测量的共振峰。
3. **声道动态轨迹重建** ＝ 模型的候选构音解释，≠ 说话人真实舌位（必须在声道重建视图常驻温和提示）。
4. **可视化插值帧（60 fps 导出由 30 fps 姿态快照插值）** ≠ 逐帧原生几何求解帧（除非用户显式开启 60 fps 快照）。
5. **VTL 物理管段合成音频** ≠ Neural Re-synthesis 神经声码器渲染音频。
6. **局部试听音频** ≠ 整乐句定稿渲染音频（局部试听重新初始化声管状态，不承诺与整段逐样本一致）。

## 9. 异常状态、空状态与性能体验边界

1. **Web Wasm 冷启动零阻塞体验 `[MVP-P0]`**：内置演示工程必须随静态资源附带预渲染缓存音频与状态轨。首次打开网页时立即允许播放和浏览，同时在顶部状态条温和提示“物理声道引擎后台初始化中”，待 Worker 就绪（约 5–6 秒）自动解锁实时拖拽与重合成，禁止用全屏 Loading 遮罩卡死首屏。
2. **长曲分块、内存与 Web 短视频 `<=1080p` 边界**：单次 VTL 序列上限 60 秒，超出时按乐句休止自动分块合成并按整数采样拼接；Web 端常驻 1 个 Wasm Worker（线性内存约 275 MiB）。舞台背景导入或拖入短视频时，超 `1080p`（例如 4K）自动等比降采样锁定至 **`<= 1920×1080`**，时间轴擦洗配合轻量 `720p` scrub 代理提示以防解码阻塞主线程与显存溢帧。
3. **构型检查与一键修复**：编辑关键帧、导入声道重建轨迹或生成连续统后自动检查每帧最小截面积；发现意外闭塞或闭塞丢失时，在时间轴与面板标黄告警并提供一键修复命令，不静默放行。
4. **联网与外部依赖降级**：AI 接口超时、配额耗尽或知乎只读接口不可用时，只降级对应面板（提示切换密钥或启用回放模式），绝不阻塞本地合成、时间轴剪辑与导出。
5. **缺字与越界拦截**：音标渲染前检查字体字形完整性；音符超出 60–600 Hz 或参数越界时明确报错并指出具体音节 ID 与合法范围。
