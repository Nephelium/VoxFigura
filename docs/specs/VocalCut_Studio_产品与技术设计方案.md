**三个结论**

1. **采用「路线 B 双层叙事（三工作区互通）」锁定赛道 01「AI × 知识与探索」**。Web 在线版默认首屏直接呈现**知乎发音探索实验室**：保留作者原文图文与富媒体展示，默认单声道大舞台并支持按需双声道滑块对比与 `6` 档离散发声态调节，在同一页面一键导出自定义像素尺寸的发音卡片；随后可由顶栏居中工作区切换直达共享同一 `.vcproj` 底座的**科研工作台**（双层 TextGrid、离散发声态锚点入轨、`F0` 与发声态单轨放大、手绘基频、拖选多音素与多音字角标切换）与**剪辑工作室**（含 `<=1080p` 视频层与 `40` 键满高定音）。
2. **技术栈确定为 Vue 3 + TypeScript + Vite 纯前端本地计算 + 极薄无数据库 Node 代理**。VTL 2.4 Wasm 物理合成、四语混排转 IPA、辅音抢拍、qTA、声道绘制、`<=1080p` 视频合成与卡片导出全在用户浏览器本地运行（科研、连续统、剪辑、导出与设置页统一联动选择本地 `WebGPU / CUDA / CPU`）；极简 Node 代理只承担服务端密钥隔离与绕过 CORS、基于词/URL 与静默黑名单的每日配额缓存，以及按职责分流的「知乎直答科普/搜索 vs 工具执行与视觉审片大模型」双通道 AI 路由。无数据库写入，天然契合知乎 AI Works。
3. **提交截止是 12 月 7 日 10:00，AI Works 正式链接需等待平台审核**。飞书官方指南明确标注 AI Works 先产出仅作者可见的 `preview` 链接，点击发布需审核通过后才生成正式公网链接。目前仓库已完成规范文档与 `v1.4` 高保真纯静态交互原型，正式 Vue 3 + Wasm + Node 代理代码尚未启动开发，必须在接下来严格按 P0 线推进，最晚 12 月 4 日至 5 日先上 AI Works 预览并提请发布过审。

6. **赛事信息的时效**。1.4 的赛程与规则读取自官方页面（页面标注更新于 2026-11-19）和技术指南（标注 11 月 10 日修改）。官方页面没有公布评审维度与权重。

## 1. 产品定位与知乎黑客松差异化

### 1.1 一句话定位

**VocalCut Studio 是一个把知乎发音问答编译成“看得见、听得着、拖得动”物理声道实验的知识探索与剪辑工作台：声音由一条逐帧可调、因果透明的声道轨迹发出。** 在第一层的**知乎发音探索实验室**，学习者与答主对比语音、方言和声乐发音差异并直接导出对比卡片回流知乎；进入底层的**科研工作台**与**剪辑工作室**，研究者与创作者在同一条以 TextGrid 为锚的时间轴上精修声道、编排辅音抢拍并输出声道演唱成片。

### 1.2 核心壁垒

按“别人多久能追上”排序：

1. **调好的构型资产与发音规则**。四个模型各有 218 个可编辑的音标起点构型，加上爆破时序、协同发音、颤音、舌形与唇形附加量，以及在 VTL 之上做的多轮几何修正。这些是一轮轮听辨和测量磨出来的，不是换个引擎就能得到的。
2. **语音学标注是时间轴的一等公民**。TextGrid 边界是所有轨道的时间锚点，构型、基频、气压都挂在音节和音段上（2.5）。剪辑软件没有这个概念，语音学工具没有时间轴剪辑，这个结合点目前是空的。
3. **物理模型之上的可解释韵律与节拍层**。qTA 靶点、辅音抢拍、五度调值换算都是有名字、有单位、可单独开关的参数。它让“这个字为什么这样唱”有答案。
4. **确定性工程加命令层，使 AI 的修改可审阅、可撤销、可复现**。神经合成可以按提示词重新生成，但做不到“把这个字尾音的声门开度调大并告诉我改前改后的测量值”。本产品里 AI 改的是参数，不是重新掷一次骰子。
5. **科研闭环**。连续统、刺激包清单、可复现卡片，再接上原工具箱已有的感知实验与标注模块，从做刺激到跑实验是连着的。
6. **已经验证过的整片出片能力**。132 秒、1080p、60 fps 的成片已经完整做出来并通过了解码与一致性检查，这不是演示用的假设。

需要清醒认识的短板：合成的自然度和可懂度不如神经网络歌声合成；引擎不是实时的；反演慢且只是模型候选解释。产品叙事应当绕开“像不像真人”，站在“看得见、改得动、说得清”上。

你问的四个问题，按规则原文回答：

1. **需要做成网页版吗？规则不强制，但实战强烈推荐优先做 Web Wasm 在线版。** 必交项“可运行体验链接”的原文是：网页提供公网链接，App、插件或桌面端提供安装包及运行说明。核查原项目后发现，M10 已具备在浏览器 Worker 中本地运行 VTL 2.4 + Python 核心的 Wasm 运行时（详见 0.2 节）。把它做成纯前端加极简 Node 代理的公网网页版，能直接解决评委不愿安装大体积 exe、Mac 评委无法运行以及社区人气奖“使用量”吃亏三个痛点。
2. **可以做成 exe 安装包吗？可以，作为备选交付。** 若选择桌面端，需同时满足“无本地开发环境可打开”和“完整操作说明”，原项目已有 PyInstaller 加 Inno Setup 流程。但在 16 天工期内，如果 Wasm 运行包能顺利重建，优先交付网页链接更稳、更省打包验证工期。
3. **需要上线到知乎吗？部署到知乎不是必要条件，但 Web Wasm 路线天然契合知乎 AI Works。** 常见问题给网页类作品提供了云主机、CloudBase、知乎 AI Works 三个托管选项，其中 AI Works 适合“前端加 Node 后端、不含数据库写入”的项目。VocalCut Studio 的声道计算全在用户浏览器本地 Worker 完成，服务端只需要一个无数据库的极简 Node 代理（转发大模型 API 与知乎接口，控制额度），正好贴合 AI Works。
4. **必须接入知乎的能力吗？规则里没有写“必须调用知乎接口”。** 但有两处硬要求绕不开：必须选一条赛道，三条赛道都以“社区 ×”开头；计划书必须写“与知乎社区生态的契合度”。所以完全不放知乎的东西在规则上可以提交，在评审上会吃亏。我的建议是放一个轻量但真实的联动，见 1.4.4。

两点规则之外的判断，供你权衡：

- 初审要在五天内滚动评完全部作品（上一季公开报道的提交量是四百多件）。评委未必会为每个作品下载安装几百兆的桌面程序，也未必在 Windows 下评审。**公网免安装的 Web Wasm 体验链接 + 3 分钟内高质量演示视频**是初审最稳的组合。
- 最佳社区人气奖按活动广场上的点赞量、使用量、评论量评选。Web Wasm 在线版让用户点开即可试听、拖动舌头并生成发音卡片，“使用量”优势明显。若改走桌面端路线，则建议额外做一个轻量网页展示页放 AI Works 兜底。

体验环境要让评委“直接操作并完整体验核心功能”，有三件事需要提前安排：

- AI 对话需要大模型密钥。不要把密钥明文写进前端代码或安装包。可行做法是通过极简 Node 代理提供带额度上限的体验配额，同时允许评委填入自己的密钥，并内置“回放模式”，断网或无密钥也能完整演示核心指令的执行与撤销。
- 首次启动要快。把演示工程的合成结果与状态轨预先缓存并随静态资源加载，评委打开页面即可播放，不用等待 Wasm 冷启动（首次下载约 30 MiB、约 5.7 秒）完成才出声音；后台静默初始化 Wasm Worker，加载完后开放实时拖动与重合成。
- 若改走桌面端路线，时间有限时只保证 Windows，在运行说明里写清系统要求，并用演示视频兜底。

#### 1.4.2 已有项目的规则：最需要先确认的一件事

规则原文（常见问题“可以用已有项目参赛吗”）：

> 参赛作品须为团队独立创作，已获奖或已公开发布的项目不得参赛。……比赛不要求重复造轮子，开源组件可以合规使用，公开创意方向可以参考；但不得搬运完整项目或仅做表面修改，作品的核心功能与主要创新必须由团队独立形成，并如实披露参考和引用情况。

相关事实：PhoneticToolbox 在 GitHub 上是公开仓库，官网提供已发布的安装包；生理参数合成是其中已发布的模块。

我的理解（不是官方解释）：

- 把 PhoneticToolbox 或其中的 M10 模块改个名字提交，属于“已公开发布的项目”和“仅做表面修改”，不可行。
- 以它和 VocalTractLab 为开源基础，做一个形态与核心功能都不同的新作品，属于“开源组件可以合规使用”，前提是新作品的核心功能与主要创新确实是新做的，并且如实披露。

据此建议：

1. **把参赛作品的“核心功能与主要创新”明确落在新做的部分上**：以 TextGrid 为锚的多轨时间轴、辅音抢拍调度、qTA 基频层、统一命令总线、AI 工具调用与提案审阅、知乎联动。这些在原项目里都不存在（见 0.2）。
2. **新建仓库，从报名期开始留下完整提交历史**。规则建议留存 AI 交互记录、设计底稿和开发日志，本文就是设计底稿之一。
3. **在计划书和仓库 README 里放一张披露表**，逐项写明：沿用了什么（VTL 2.4 引擎及其许可、原项目的引擎适配层、轨迹与爆破时序、文本转 IPA、构型库等），新做了什么。
4. **尽早向官方小助手确认**，不要等到提交前。可以直接这样问：“我有一个已开源的语音学工具箱，其中包含基于 VocalTractLab 的声道合成模块。我想以它为底层引擎，新做一个多轨剪辑加 AI 对话控制的独立应用参赛，并在计划书中披露沿用部分。这样是否符合参赛要求？另外，是否要求全部开发在 12 月 5 日至 7 日的提交窗口内完成？”

还有一处需要你自己判断：2.7 节建议以原项目的双声部剪辑页为起点扩展时间轴，这样最省时间。如果赛事方对“沿用已有代码”的口径偏严，就改为参考其数据模型重新实现时间轴组件，工作量在 5.3 的 P0-3 上再加约 2 人日。我不清楚双声部剪辑页是否已随公开版本发布，这一点也会影响判断。

#### 1.4.4 知乎开放能力对接（已核实 REST API 契约与 AI 接入能力边界）

通过官方 `zhihu-cli-skill`（v0.7.5）及飞书《知乎黑客松S3- 技术指南》核实，知乎开放平台已提供完整 HTTPS REST API（统一采用 `Authorization: Bearer <ZHIHU_ACCESS_SECRET>` 与秒级 `X-Request-Timestamp` 请求头）。Node 代理层直接调用 REST 接口即可，无需在服务端套壳运行 `zhihu-cli.exe`：

| 接口 | 用途 | 路线 B 对接位置 | 实测限制与避坑铁律（已于 `2026-11-22` 实调 `/api/v1/quota` 核验） |
| --- | --- | --- | --- |
| `GET /api/v1/content/zhihu_search` | 知乎搜索（关键词检索，返 `Title`、`ContentText` 摘要、溯源 `Url`、`VoteUpCount`、`AuthorName`、精选评论） | 首页搜索框 + **随机一题**关键词抽题（**主力高配额入口**） | `Count` 最大 10，`HasMore` 固定 `false`；**实测日额度 5,000 次**；**按 `AuthorName` 静默过滤随机抽题必须走此接口** |

### 2.5 时间锚点模型与三轨时间锁定

三轨锁定不是一个额外功能，而是数据模型的直接结果：**绝对时间是算出来的，存下来的是“锚点 + 局部坐标”**。

- TextGrid 的区间边界是主锚点，以整数采样存储。
- 声道关键帧、基频靶点与残差、气压包络点都不存绝对时间，而存“属于哪个区间 + 区间内的位置”。位置有两种写法：
  - 弹性项存归一化位置 `u ∈ [0, 1]`，随区间伸缩。例：元音稳态的姿态帧、基频残差控制点、气压包络点。
  - 刚性项存相对某一边界的固定偏移（毫秒）。例：塞音除阻相对闭塞结束的时刻、送气与 VOT、过渡斜坡的封顶时长。
- 用户拖动一个音节边界，只改了一个锚点的采样号。编译时所有挂在相邻两个区间上的对象重新算出绝对时间：弹性项按比例伸缩，刚性项保持原时长，基频靶点区间跟着变并重跑 qTA。没有任何数据被破坏性重采样，把边界拖回去就完全复原。
- 相邻区间放不下刚性项时，拖动在该处被阻挡并提示原因（例如“该塞音至少需要 11 ms”）。
- 锁定可以按轨解除：解除后该轨对象改存绝对采样号，不再跟随边界。再次锁定时按当时所在区间重新计算局部坐标。

同构 TextGrid 的节奏迁移（3.3.6）就是一次性移动所有边界，执行的是同一个 `retime()`。

决策与理由：

1. **为什么选择 Vue 3 纯前端全本地计算 + 极薄无数据库 Node 代理**。
   - **所有语音学与音频视频算法都在用户浏览器本地运行**：包括文本转 IPA、辅音抢拍调度、qTA 基频求值、VTL 2.4 物理声道合成（原项目已验证 Pyodide 0.29.3 + Emscripten 4.0.9 Wasm 侧模块，`vocal-runtime.zip` 仅 468 KB，姿态中位数 21.3 ms，5 s 序列 5.97 s）、2D/3D 声道矢量绘制与 WebCodecs 卡片/成片编码。
   - **未来轻量化神经模型也可下放到用户电脑本地计算**：赛后蒸馏出的轻量 TensorTract3 ONNX（10–20 MB）与神经残差插值模型通过 `onnxruntime-web` 直接下放客户端，在设置页提供计算设备选择器，让用户自由切换 **本地 GPU（WebGPU）** 或 **本地 CPU（WASM）**（桌面端可进一步挂载 CUDA / DirectML / CPU）。
   - **极薄 Node 代理依然不可或缺，但零数据库写入**：① 知乎 `ZHIHU_ACCESS_SECRET` 和大模型密钥绝不能放进浏览器源码，且浏览器无法直连知乎开放平台接口（CORS）；② 账号免费日额度共享，需要代理层做按关键词与问题 URL 的短期缓存和随机推荐静默屏蔽名单；③ P1 阶段未蒸馏的 `WavLM-large`（1.18 GB）反演必须由云端 API 转发。无数据库设计也正好完美适配知乎 AI Works 托管规则。
2. **以二重唱编辑器为起点扩展，先收窄首版范围**。它已经有整数采样时间线、半开区间、片段模型、分割与复制粘贴、撤销栈、字幕、镜头关键帧和视频导出。黑客松首版聚焦核心联动轨（双层 TextGrid、声道关键帧 `ART`、`PHON` 离散发声态、手绘与 qTA 共存的 `F0`、自由手绘 `PS` 气压包络与波形/视觉轨），波纹编辑与完整 `JKL` 快捷键放到赛后。
3. **直接复用 `PhoneticToolbox_v3` 的模块化 `embed.mjs`（2026-11-20 重做 2D/3D 声道可视模型）并彻底隔离三类可移植模型包**：原声道页的复杂界面壳不整体迁移，但其最新抽离出的 `frontend/public/vocal-tract/embed.mjs`（`mountVocalTract` 无框架耦合入口）与 `VTL 2.4` + `TensorTract3` 是本项目所有生成发音与声道可视化的**强制真实模型基线**；严禁用脱离底层物理状态的假轮廓代替真实声道生成，且二维模型、三维模型、自训神经模型必须按统一契约打包导出，确保任何外部项目可直接引入复用到自己工程中。
4. **内核抽成独立包，明确切分边界避免双端撕裂**。新算法一律写成不依赖界面与引擎的纯函数，配快照测试。每个算法只实现一次：
   - **TypeScript 一侧**：文本转 IPA、音节计划、语音/歌唱调度（完整继承 `numbered-score.ts` 简谱语法含 `p/pp/ppp/f/ff/fff` 强弱标注）、**纯时序层的爆破默认时长与下限预算**（把 `stop_timing` 中不依赖 VTL 几何的时长规则迁到 TS，避免 TS 调度器与 Python `stop_timing` 双端重复维护或跨进程往返）、靶点解析、qTA 求值、重定时。求值结果按固定控制周期（如 2.5 ms 或 5 ms）输出密集 `f0_hz[]` 与 `pressure_pa[]`（含非钢琴纯 IPA 手绘音强曲线与 `±120 Pa` 强弱特征偏移）数组交给引擎。
   - **Python 一侧（`vocalcut_core`）**：直接接收调度好的控制帧与密集 `f0_hz[]` / `pressure_pa[]`（**新增密集控制通道，绕开旧 `trajectory.py` 中 `validate_pitch_curve` / `validate_pressure_curve` 的 201 点硬编码上限**），执行轨迹插值、协同发音、几何截面积计算、构型检查，以及赛后的关键帧检测与连续统。
5. **每个说话人独占一个 VTL 单例，Web 端按需串行预渲染**。VTL 初始化是进程/Worker 级单例。桌面端可用多进程并行；Web 端每个 Wasm Worker 线性内存约 275 MiB，建议默认常驻 1 个 Worker，多声部切换说话人时串行预渲染并写入内容摘要缓存（PCM + 状态轨），既控内存又保证响应稳定。
6. **编译前半段留在 TypeScript**。文本转 IPA 的全部规则现在在前端，没有 Python 对应实现。浏览器界面与赛后 Node 无界面出片共用同一份 TS 编译代码。
7. **调度器与纯爆破时序统一归属 TS**。原项目语音时长规则在前端、歌唱调度在 Python `singing.py`，且 `singing.py::_edges` 强依赖 `stop_timing` 的闭塞/释放下限与 `release_type()`。新架构将两者统一收口到 TS 调度包，Python 侧只保留从已定时的关键帧/标志点与密集控制数组到声道几何与音频的合成部分。
8. **许可证随引擎走**。引擎适配层、原生补丁与 Wasm 侧模块均为 GPL-3.0-or-later，分发时须同步提供对应源码（原项目 `build_m10_wasm.py` 已内置 `corresponding-source.zip` 生成）。详见 6.1。
9. **三类模型独立可移植与零 UI 耦合打包规范**：
   - **二维声道视图包（2D Sagittal）**：遵循 `embed.mjs` `view: 'sagittal'` 契约，零 WebGL 依赖，纯消费引擎 `{ metadata, state }` + `pose` 回调，独立导出供任意前端/WebView 使用；
   - **三维声道模型包（3D Vocal Tract）**：沿用 `embed.mjs` `view: 'model'`（`head-model.mjs` / `face-model.mjs` / `anatomy.mjs` / `geometry.mjs`），以 Standard ES Module + `importmap` 打包供外部 Web/Electron/Qt 项目一键挂载；
   - **自训神经模型包（`TensorTract3` / ONNX）**：权重（`.pt`/`.onnx`）+ `model.manifest.json`（输入 `16 kHz`、输出 `50 Hz 27D m27 + pressure_pa + f0_hz`、WebGPU/CUDA/CPU 执行后端声明）+ 纯推理脚手架与 Vue UI 彻底解耦，确保第三方便捷接入自身管线。

### 2.9 发音卡片导出

**是什么**：把一个音、一个字或一个词导出成一段几秒到十几秒的短视频。画面里声道剖面在动，旁边是文字和 IPA，声音由这条声道合成。它是给“这个音到底怎么发”这类问题准备的答案载体，可以贴进知乎的回答、想法，也可以放进课件。

**为什么值得做**：

- 它让产物回到社区。1.4.5 的叙事是“文字答不清的发音问题，让答案自己张嘴”，卡片就是这个答案的成品形态。
- 用到的都是现有能力：文本转 IPA、合成、剖面绘制、视频导出。新做的只有版式和一条固定的出片路径。
- 它不依赖知乎接口，也不依赖剪辑台界面，进度上可以和主线并行。

#### 2.9.1 三种卡片

| 类型 | 内容 | 例 | 版本 |
| --- | --- | --- | --- |
| 对比卡（首版主打） | 两个音并排，同步或交替播放，差别最大的发音器官高亮 | 汉语“算” `[swan⁵¹]` vs 英语“swan” `[swɒn]`（知乎 `question/664643748/answer/3598793264`）、n 与 l、粤语入声 `-p/-t/-k` | **P0 首版必交** |
| 单音卡 | 一个音或一个音节。常速播放一遍，慢放一遍 | `[ʈʂ]`、“张” | **P0 首版必交** |
| 过程卡 | 一个词或一句短语，逐音节显示 IPA | “湾区” | 赛后 |

对比卡是最贴近知乎提问方式的一种，因为发音问题大多是“某两个音怎么区分”。它与连续统（3.4.4）共用两端构型的对齐结果。

#### 2.9.2 版式与时间结构

默认画幅 1080 × 1080，可选 1080 × 1920。四个区域：

| 区域 | 内容 |
| --- | --- |
| 顶部 | 文字、IPA、转写（拼音、粤拼等）与来源问题标签 |
| 中部 | 声道矢状剖面（对比卡左右并排 A/B）。最窄处与差异器官高亮；可选洋葱皮显示前一姿态 |
| 底部 | 波形与播放头，当前音段的 IPA 高亮 |
| 脚注 | 说明文字、来源链接与产品名 |

单音卡的时间结构：静止 0.3 秒，常速带声播放，停 0.4 秒，慢放带声播放（默认 0.4 倍速），末帧停 0.5 秒。总时长控制在 6 到 15 秒。各段时长是模板参数。

几个做法上的决定：

- **高亮位置由计算得出，不靠人工标注。** 单音卡高亮口腔最小截面积所在的位置，这个量引擎直接给出（3.5.6）。对比卡高亮两端构型里归一化差值最大的那几个参数对应的器官。
- **慢放的画面是模型帧，不是图像插值。** 轨迹可以在任意时刻取值，慢放时按更密的时间步取构型再绘制。声音在首版用现有的变速处理保持音高；后续可以改为让调度器只拉长弹性段后重新合成（2.5），那样爆破和送气不会被拉长。
- **说明文字默认显示**，内容为“由物理声道模型合成，非真人录音；声道形状为模型示意”。这是 6.5 的原则在卡片上的落实。卡片会离开产品单独传播，观看的人看不到任何别的说明。
- **IPA 字体要做缺字检查。** 导出前确认卡片上的每个字符在所用字体里有字形，缺字时拒绝导出并指出是哪个字符。

#### 2.9.3 输出与入口

输出文件：

| 文件 | 说明 |
| --- | --- |
| `.mp4` | 主输出，带声音 |
| `.gif` | 可选，无声，适合直接贴进知乎回答和想法配图 |
| `.png` | 封面帧 |
| `.card.json` | 配方：文本、IPA、说话人、构型库版本、引擎版本、种子、模板参数。用它可以原样重新生成这张卡片 |

知乎对回答和想法里视频、动图的格式与大小限制没有核实，定输出规格之前要先查。

**主入口收拢在首屏「知乎发音探索实验室」右侧操作区**（随当前单音探索或双音对比模式一键导出，支持预设比例与自定义像素宽高 `W×H`，与知乎问答检索、双声道实验构成单页社区闭环）；音标表里选中一个音、时间轴选区和 AI 工具 `card.export`（4.2）提供快捷直达跳转，科研工作台与剪辑工作室各自保留专属工程/波形/视频导出入口，不再重复放卡片导出。

#### 2.9.4 实现路径

```text
文本或 IPA ──▶ 文本转 IPA ──▶ 语音模式调度 ──▶ 合成（常速）
                                                   │
                         面积函数 ──▶ 最窄处位置 ──┤
                                                   ▼
                              卡片模板（3.5.3 的模板机制，内置三套版式）
                                                   │
                                                   ▼
                                    现有导出管线 ──▶ mp4 / gif / png / card.json
```

首版走一条独立路径：输入文本或 IPA，直接出文件，不经过时间轴界面。这样它只依赖引擎进程和迁入的导出代码。卡片模板是一个只读的内置工程，输入只做整值替换，与 3.5.3 的约束一致。

验收：

- 同一份 `.card.json` 两次导出，音频哈希相同，视频帧数相同。
- 时长、分辨率在模板设定范围内；说明文字存在。
- 含缺字字符的输入被拒绝并给出原因。

工作量粗估：单音卡 1 人日，对比卡再加 0.5 人日。这个估计的前提是现有导出管线迁入新仓库后可以直接复用，这一点没有验证。

## 3. 五大核心技术问题：算法选型与落地方案

### 3.1 qTA、手绘基频与微扰的分层耦合

**结论**：所有基频运算统一在半音域（相对说话人参考频率）进行，分六层自下而上求值。qTA 负责“怎么过渡”，手绘负责“局部要什么”，两者不争同一份数据：手绘优先尝试改写成靶点，改写不了的部分才存为残差；需要逐点精确时用“钉住”模式，并把钉住区出口的运动状态回灌给后面的 qTA，这样既不跳变，也不丢手绘。

#### 3.1.1 分层结构

| 层 | 名称 | 存什么 | 谁写入 | 求值方式 |
| --- | --- | --- | --- | --- |
| L0 | 音域基准 | 参考频率 `f_ref`、音域下限与跨度（半音） | 说话人配置 | `st = 12·log2(f / f_ref)` |
| L1 | 靶点层 | 每个靶点区间一条 `(m, b, λ)`，带来源标记 | 默认韵律、简谱/钢琴、迁移、用户 | 按优先级解析成唯一靶点序列 |
| L2 | qTA 动力学 | 不存数据，纯函数 | 无 | 三阶临界阻尼逼近，跨区间传递 F0、速度、加速度 |
| L3 | 手绘层 | 残差片段 `δ_k`、钉住片段 `pin_k` | 用户手绘、PitchTier 导入、迁移残差 | 残差相加；钉住区替换并回灌状态 |
| L4 | 表现层 | 颤音（速率、深度、延迟、渐入渐出）、滑音修饰 | 歌唱模式、用户 | 确定性函数，按音分相加，连音保持相位 |
| L5 | 微扰层 | flutter 强度、shimmer 强度、随机种子 | 全局或区段特征 | 带种子的确定性伪随机；flutter 由引擎声源执行 |
| L6 | 约束与清浊 | 声源可用范围、清音掩蔽 | 引擎能力表 | 越界报错而非静默夹紧；清音段 F0 不输出但 qTA 状态照常推进 |

合成公式（半音域相加，最后回到 Hz）：

```text
Q(t)      = qTA(靶点序列, 初始状态)                    # L1 + L2
S(t)      = Q(t) + Σ_k w_k(t)·δ_k(t) + V(t)            # 残差 + 颤音；钉住区内 Q(t) 被 pin_k(t) 替换
F0_ctl(t) = f_ref · 2^(S(t) / 12)                      # 控制基频：界面曲线与科研导出的默认对象
F0_eff(t) = F0_ctl(t) · (1 + flutter(t; seed))         # 声源内部实际使用，仅在需要时导出
```

原项目的 flutter 已经写入 VTL 声源并按种子复现（`m10/source-2`），shimmer 作用于声门振幅而非基频，Schoentgen jitter 已停用。新架构沿用这一分工：微扰永远不回写手绘曲线，`F0_ctl` 与 `F0_eff` 分开导出，科研导出默认给 `F0_ctl` 并附微扰参数与种子。

#### 3.1.2 L1 靶点解析：四种来源怎么共存

每个靶点区间保存一个候选列表，解析时取优先级最高的非空项：

```text
user（用户直接改靶点） > transfer（参考音迁移拟合） > score（简谱/钢琴） > default（文本默认韵律）
```

- **语音模式**：靶点区间等于音节。`default` 来自 3.2 节的规则，`score` 通常为空。
- **歌唱模式**：靶点区间等于音符。一字多音时一个音节内有多个靶点区间。`score` 给出静态靶点 `m = 0, b = 音符音高`；`default` 默认不参与，可选开启“保留调形”，把词调以有上限的偏移叠加到音头或音尾（原项目歌唱规划已提出这一选项）。
- 每个候选都记录来源和生成规则名，界面可逐字查看“这个音高是谁定的”，AI 也只能通过声明来源的指令写入。删除高优先级候选即自动回落到下一级，不需要“恢复默认”这类特殊逻辑。

#### 3.1.3 L2 qTA 求值

为与 Prom-on 等（2009）原文及 3.2.2 斜调终值保持严格一致，**全文统一规定靶点截距 `b` 为音节/区间末尾（offset）处的取值**（记作 `b_end`）。设区间时长为 `D`，局部时间 `t ∈ [0, D]` 从区间起点计，则靶线方程与等价起点截距为：

```text
x(t)    = m·(t − D) + b_end = m·t + b_start，其中 b_start = b_end − m·D
f0(t)   = x(t) + (c1 + c2·t + c3·t²)·e^(−λt)
c1      = f0(0) − b_start
c2      = f0'(0) + c1·λ − m
c3      = ( f0''(0) + 2·c2·λ − c1·λ² ) / 2
```

当斜率 `m = 0`（平调或歌唱静态音符）时，`b_start = b_end = b`。

边界状态传递与重置规则：
- 连续音节/音符之间，前一区间末尾的 `f0、f0'、f0''` 直接作为下一区间的初始状态，保持位置、速度、加速度连续，不需要额外平滑。
- **语音模式句首或长停顿后**：初始 `f0(0)` 取说话人音域中点，速度与加速度为零。
- **歌唱模式乐句首音或长休止（默认 > 150 ms）后**：初始 `f0(0)` 默认直接对齐到该首音符的靶点高度 `b_end`（允许可选的小幅起音弯音，如 −0.5 到 0 半音），速度与加速度为零；避免休止后唱高音时从音域中点拉出违和的长滑音。

`λ` 决定逼近快慢。对阶跃靶点，剩余偏差为 `e^(−λt)·(1 + λt + (λt)²/2)`，由此可直接算出到位时间：

| λ（1/s） | 完成 50 % | 完成 90 % | 完成 95 % |
| --- | --- | --- | --- |
| 20 | 134 ms | 266 ms | 315 ms |
| 40 | 67 ms | 133 ms | 157 ms |
| 60 | 45 ms | 89 ms | 105 ms |
| 80 | 33 ms | 67 ms | 79 ms |
| 100 | 27 ms | 53 ms | 63 ms |

（对应 `λt ≈ 2.67 / 5.32 / 6.30`。）这张表是给歌唱模式定默认值用的：音符要在元音踩拍时基本到位，而有字头辅音时靶点区间从抢拍的辅音起点就开始（见 3.3 节），所以辅音前导量本身就是滑音时间。前导量 80–120 ms 时，`λ` 取 60–80 可在踩拍点完成 90 % 以上；语音模式取 30–55 更接近自然语流的滞后。**但对零声母或极短字头（前导量 < 50 ms）**，不能等到踩拍点才切换靶点，否则元音起始会明显滞后；歌唱模式对此类音符启用“预滑（pre-glide）”：将靶点切换时刻提前到前一音节尾部（默认提前 `min(45 ms, 前一韵核剩余持音的 25 %)`），或为该音符自动调高 `λ` 至 90–110。以上默认值均作配置项，需经听辨校准。

**文献对照**。qTA 原始论文（Prom-on、Xu 与 Thipakorn，2009，表 V）以音节末尾为时间零点（与本节 `b_end` 定义完全一致），对普通话的拟合均值如下，`b_end` 为相对句首 F0 的半音数：

| 声调 | m（半音/秒） | b_end（半音） | λ（1/s） |
| --- | --- | --- | --- |
| 阴平（高） | 0 | 0.0 | 54.5 |
| 阳平（升） | +93.4 | −2.2 | 40.7 |
| 上声（低） | 0 | −8.9 | 34.1 |
| 去声（降） | −106.4 | −2.5 | 39.3 |

论文中 `λ` 的搜索范围为 0–120，三阶系统的平均值约 44.6。这组数有两个用处：

- 可以直接作为语音模式普通话的默认靶点（按上式自动换算 `b_start = b_end − m·D`，例如 0.2 秒的阳平起点靶值为 −20.88 半音、终点 −2.2 半音，不会跑飞）。
- 它说明了一件事：拟合出的升降调斜率在 ±100 半音/秒上下，远陡于把五度值直接连线得到的斜率（例如 35 调在 10 半音音域、0.2 秒音节里只有 25 半音/秒）。靶线必须比表层曲线陡，实际曲线才能在音节内追上。所以 3.2.2 由五度值换算的斜调靶点只能作初值，必须经过那里说的“单字调校准”才能命中记音值。

本次没有查到专门把 qTA 用于歌唱的研究。歌唱模式“每个音符一个静态靶点”是本方案的工程延伸，不是文献结论。qTAtrainer 等工具的下载页没有声明许可证，本方案只按论文公式自行实现，不引入其代码。

**生理合理性检查**：Xu & Sun (2002) 给出了人声变调的最快速度经验式。可以据此做一个只提示不拦截的检查：某区间要求的变化幅度在可用时长内超出该上限时，在基频轨上标黄，并提示“延长前导量或降低跳进幅度”。花腔和大跳是它最常触发的地方。

#### 3.1.4 L3 手绘：三种写入方式

用户在基频轨上画一笔，松手后按以下顺序处理：

1. **靶点回写（整形）**。笔画覆盖某个靶点区间的大部分时，先尝试把它解释成靶点。固定 `λ` 时模型对 `(m, b)` 是线性的（上式中 `c1、c2、c3` 都是 `m、b` 的一次式），所以可以对 `λ` 做一维网格搜索，每个 `λ` 用闭式最小二乘解 `(m, b)`，取误差最小者，写为 `user` 候选。拟合后的剩余误差低于阈值（建议 0.3 半音 RMS）就到此为止，曲线仍然完全由 qTA 生成。
2. **相对残差（默认）**。拟合解释不了的部分，以及只覆盖区间一小段的局部笔画，存为残差片段 `δ_k`：稀疏控制点、PCHIP 插值（不过冲）、片段两端用 30 ms 升余弦窗 `w_k` 羽化到零。残差坐标存的是“所属区间 ID + 区间内归一化位置”，所以移调、改时长、拖动 TextGrid 边界、重跑抢拍调度后，这一笔都跟着走。
3. **绝对钉住**。科研场景要求“这一段就是这条 Hz 曲线”（例如导入 PitchTier 做刺激）。钉住区内 `Q(t)` 被替换。两端这样处理：
   - 入口：把入口前 20–40 ms 作为过渡带，qTA 输出与钉住曲线按升余弦交叉；或者在导入时勾选“首点吸附”，直接把钉住曲线平移到与 qTA 相接。
   - 出口：对钉住曲线末尾 30–40 ms 做二次最小二乘拟合，得到出口处的值、速度、加速度（加速度做限幅），作为下一个靶点区间的初始状态重新启动 qTA。后一个字是从手绘终点按动力学逼近自己的靶点，而不是从“假如没画过”的位置硬切回来。

三种方式在界面上是同一支笔，差别只在右侧属性区的“写入方式”选项，默认“自动”（先 1 后 2）。钉住需要用户显式选择，因为它会让该段脱离靶点联动。

#### 3.1.5 求值顺序与实现要点

```text
resolve_targets()            # L1：每区间取最高优先级候选
for 区间 i in 时间顺序:       # L2 + L3 钉住
    if 区间与钉住片段相交: 分段求值，出口状态由钉住曲线拟合得到
    else: 闭式求值，状态传给 i+1
S = Q + Σ w_k·δ_k            # L3 残差
S += vibrato(t)              # L4，仅在持音区且超过最短时长时启用
检查 60–600 Hz 等声源范围      # L6，越界即报错并指出是哪个字、哪一层造成的
按引擎控制周期采样后送入声源    # L5 的 flutter 在声源内执行
```

- 存储始终是稀疏的（靶点、控制点、参数），按引擎控制周期现算，不再受“整段曲线最多若干个点”的限制，长曲和快颤音都不会欠采样。
- qTA 在清辅音和静音段照常推进，只是不发声；界面用虚线画出这段隐藏轨迹，用户能看到下一个元音将从哪个音高起步。
- 整个求值是纯函数，输入不变则逐采样一致，可直接做快照回归测试。
- 靶点、残差、钉住、颤音、微扰在基频轨上分别可单独开关，便于回答“这段不自然是哪一层造成的”。

### 3.2 文本转 IPA 后的初始基频靶点生成

**结论**：不引入神经韵律模型。用一个统一的中间表示“调级串”（五度制的泛化）把各语言的词汇韵律翻译成 qTA 靶点，再按 PENTA 的思路把句子层面的功能（语调、焦点、边界、下倾）作为对靶点的并行修饰叠加上去。全部是查表加规则，毫秒级完成，每个靶点都能追溯到生成它的规则。

#### 3.2.1 统一管线

```text
文本 ──G2P──▶ 音节序列（IPA + 词汇韵律标记）
        │
        ├─ ① 词汇层：声调 / 重音 / 音高重音 ──▶ 每音节一个调级串，如 55、35、21+4、H、L
        ├─ ② 变调与连读规则（按语言或方言包）──▶ 改写调级串
        ├─ ③ 调级串 ──▶ qTA 靶点 (m, b, λ)
        └─ ④ 句子层修饰：下倾、边界调、焦点、停顿重置 ──▶ 调整 b、音域缩放与 λ
```

原项目已具备的部分直接接入：汉字转 IPA 的十套转写标准、CMUdict、假名按拍处理、个人词典、五度调值预览、普通话连读建议、英语句末升降选择。新增的只是第 ③④ 步和日语、方言的第 ①② 步数据。

#### 3.2.2 调级串到 qTA 靶点的换算

设说话人语音音域下限为 `st_lo`、跨度为 `R` 半音（语音模式默认取 8–12，可在说话人配置里改），五度值 `d ∈ [1, 5]` 映射为 `st(d) = st_lo + (d − 1)/4 · R`。音节时长为 `D`。

| 调级串形态 | 例 | 靶点（按 3.1.3 统一末尾截距 `b_end`） |
| --- | --- | --- |
| 平调 `aa` | 55、33、11 | 静态：`m = 0`，`b_end = st(a)`（等效起点 `b_start = st(a)`） |
| 斜调 `ab` | 35、51、24 | 动态：`m = (st(b) − st(a)) / D`，`b_end = st(b)`（等效起点 `b_start = st(a)`，靶线在音节末到达 `st(b)`） |
| 折调 `abc` | 214、313、242 | 音节内拆成两个靶点区间，默认在 40 % 处切分：前段 `ab`（`b_end = st(b)`）、后段 `bc`（`b_end = st(c)`） |
| 短调（入声等） | 5、3、21 加短标记 | 静态或短斜调，同时把时长模型系数调短，并交给韵尾构型（喉塞、不除阻塞音）处理 |
| 轻声或弱读 | 0 | 静态中值靶点，`λ` 取弱值，音高主要由前一音节的惯性决定 |

两点说明：

- qTA 的靶点是“想去的地方”，实际曲线会滞后，短音节里到不了位。这符合自然语流，默认保留。方言记音给的五度值是表层描写，如果研究者要求单字调的表层曲线严格落在记音值上，可开启“单字调校准”：在孤立音节条件下对靶点终值做一维搜索，使合成终点命中记音值，把校准后的靶点存入方言包。
- 折调的切分比例、各语言的 `λ` 默认值都放在语言配置里，不写死在代码中。

#### 3.2.3 各语言的词汇层与变调规则

| 语言 | 词汇层数据来源 | 默认靶点 | 规则 |
| --- | --- | --- | --- |
| 普通话 | 现有汉字转 IPA 与声调标注 | 阴平 55 静态高；阳平 35 动态升；上声默认 21 静态低，仅在停顿前用 214；去声 51 动态降；轻声弱靶点 | 上上变调、“一”“不”变调、半上；沿用现有“连读建议”并改为可逐字采纳的规则输出 |
| 英语 | CMUdict 重音位 0/1/2 | 非重读：中值弱靶点；次重音：中高静态；主重音：高静态 | 核心重音默认落在句内最后一个实词，音域上扩；其后音域压缩。陈述句末低降，是非问句末升，逗号处续升。沿用现有“逐短语选择句末升降” |
| 日语 | 需新增音高重音词典（见下） | 按拍给 H / L 静态靶点 | 重音短语首拍低、第二拍起高、重音核之后降为低；无核型保持高并缓降；重音核之后的短语整体降阶 |
| 自定义方言 | 方言包里的调类表（3.2.6） | 有录音拟合的靶点就用它，否则由五度值按 3.2.2 换算 | 方言包里的变调规则表，三种写法：成对规则、整词调型、特定词规则（3.2.6） |

日语的音高重音无法从假名推出，需要词典。可选方案是 OpenJTalk 系的分析器配合带重音信息的词典，引入前需核对其许可证与体积。没有词典或查不到时回落为“无核型”（首拍低、其后高并缓降），在预览里标注“近似”，这仍然比全平好。

方言没有提供变调规则时，使用单字调加句子层修饰，并在界面提示“未配置连读变调”。

#### 3.2.4 句子层修饰

句子层不产生新靶点，只修饰已有靶点，四项互相独立、可单独关闭：

- **下倾**：靶点高度随短语内时间线性下降，默认整句下降 2–4 半音，遇到句号或长停顿重置，逗号处部分重置。
- **边界调**：按标点和句类修改短语末一到两个音节的靶点（陈述降、疑问升、未完续升）。普通话疑问句不改调型，只整体抬高并扩大句末音节音域。
- **焦点**：用户或 AI 标记焦点词后，焦点词音域扩大，焦点后音域压缩并整体降低，焦点前不变。未标记时不施加。
- **弱化**：功能词、轻声、非重读音节降低 `λ` 并缩短时长，让它们更多受邻近音节牵引。

每项修饰以 `{规则名, 参数, 作用范围}` 记在靶点的来源链上。这样用户问“为什么这个字低”，界面能答出“去声靶点 51，叠加句末降 −2 半音，叠加下倾 −1.3 半音”。

#### 3.2.5 为什么这样够“轻量且合理”

- 全部数据是几张表：调类表、变调规则表、重音词典、语言参数。新增语言或方言等于新增一个数据包，不改引擎。
- 输出是靶点而不是曲线，后续的简谱定音、手绘、迁移都作用在同一结构上，初始韵律不会成为一条难以修改的死曲线。
- 规则透明，适合作为实验语音学的基线条件：研究者可以关掉某一项修饰做对照，这是端到端模型给不了的。
- 默认值（音域跨度、下倾量、焦点缩放、各调 `λ`）在首版以文献常用量级起步，随后用少量母语者朗读语料跑一遍靶点拟合来校准，校准结果作为语言包的版本化数据发布。

#### 3.2.6 方言包里的声调数据

方言的声调要解决四件事：调值存在哪里，连读变调怎么写，调值从哪里来，入声怎么处理。

**一、转写表只输出调类，调值挂在调类表上**

转写表把文字转成“音节加调类”。调类是一个不带数值的标签，例如 `T1`、“阴平”。调值、时长、发声类型都记在调类表里。这样改调值不用动转写表，换发音人也只换调类表。

| 字段 | 含义 | 例 |
| --- | --- | --- |
| `id`、`label` | 调类标识与名称 | `T3`、“上声” |
| `levels` | 五度调级串，按 3.2.2 换算成靶点 | `"21"` |
| `variants` | 按位置取用的变体：停顿前、非末字、轻读 | 停顿前用 `"214"` |
| `dur_scale` | 相对时长系数 | 舒声 1.0，入声 0.5 |
| `checked` | 是否促声（入声） | `true` |
| `coda_release` | 入声韵尾的处理：不除阻、喉塞、正常除阻 | `"unreleased"` |
| `phonation` | 伴随的发声类型：声门预设名、混合量、作用位置（全程、低点、后半） | 低点处混入嘎裂声 |
| `targets` | 录音拟合或校准得到的 qTA 靶点。有它就不再用 `levels` 换算 | 见下 |
| `source` | 调值来源：记音、校准、录音拟合；附样本数与拟合误差 | |

`phonation` 是可选字段，不填就是常态发声。它用来表达声调与嗓音质量绑定的情形，例如普通话上声在低点常带嘎裂声，一些吴语的阳调类带气声。预设名必须存在于说话人文件中，否则导入时报错。

`targets` 里的高度和斜率按音域归一化后存储：高度用连续的五度值，斜率用五度每秒。合成时按当前说话人的音域下限与跨度还原成半音。这样同一张调类表用在男声和女声说话人上都成立。

**二、变调规则有三种写法**

| 写法 | 形式 | 适用 |
| --- | --- | --- |
| 特定词规则 `lexical` | 某个字或词在某种环境下改用某个调级串 | 普通话的“一”“不” |
| 整词调型 `word_pattern` | 按首字调类和词长，给出整个词的调级串序列，后字的原调不起作用 | 吴语里常见，如上海话的广用式变调 |
| 成对规则 `pair` | 按前字调类、后字调类和作用域，改写前字或后字。调类可以写通配符 | 普通话上上相连；用通配符可以表达闽语里常见的“非末字一律变调” |

应用方式：

- 顺序固定为特定词规则、整词调型、成对规则。前面的规则命中后，后面的规则不再改同一个音节。
- 作用域来自分词结果（韵律词或短语）。成对规则在域内按配置的方向扫描一遍，默认从左到右。
- 每个音节最多被改写一次，规则不递归。这保证结果确定、一定终止。
- 每次改写记入靶点的来源链（3.2.4），用户可以逐字拒绝。
- 没有分词结果时，只对相邻两字应用成对规则，并把结果标为“建议”。三个上声相连这类情形的结果取决于词的结构，没有分词就无法判断。

不属于连读变调的调类变化（小称变调、粤语的变音等）不写成规则，直接在个人词典里给该词标注调类。

**三、调值的三个来源**

| 来源 | 做法 | 评价 |
| --- | --- | --- |
| 记音的五度值 | 按 3.2.2 换算 | 最快。误差也最大：3.1.3 说明了靶线必须比表层曲线陡，直接换算的斜调会追不上 |
| 单字调校准 | 3.2.2 已有：搜索靶点终值，使合成结果命中记音值 | 不需要录音。只保证终点，不保证曲线形状 |
| 录音拟合 | 见下 | 最可靠。得到的是这位发音人的调值 |

录音拟合的步骤：

1. 每个调类录若干单字，建议不少于 5 个。尽量选鼻音、边音或零声母的音节，清辅音声母会造成基频缺段和起始处的扰动。
2. 提取基频并转成半音，去掉首尾不稳定的部分。
3. 用全部样本的基频分布确定这位发音人的音域下限和跨度（默认取 5 % 与 95 % 分位），把基频折算成连续五度值。方言声调实验里常用的 T 值归一化是同一思路。
4. **交互手绘修正（五度调值 + 连续基频双轨手绘）**：在方言包工作室内，除通过点击/拖拽绘制**赵氏五度调值目标曲线 SVG** 之外，**同样允许用户直接自由手绘方言连续基频 `F0` 曲线**，并将手绘连续曲线叠加写入当前样本或调类测试的密集控制序列，便于细致拟合地域特色滑音与微升微降。
5. 每个调类做时间归一后求平均曲线，拟合 qTA 靶点。初始状态取实测起点，速度和加速度取零；对斜率、高度、逼近速率做网格搜索加局部细化，使均方误差最小。折调多一个切分比例。
6. 各调类的平均时长之比写入 `dur_scale`。
7. 报告每个调类的拟合误差和样本数。误差偏大时提示可能需要拆成两段靶点，或者样本有问题。
8. 结果写入 `targets` 和 `source`，同时反推一个五度调级串写入 `levels` 供显示。

两点限制要写进包的元数据：拟合结果是这位发音人的单字调，不是该方言的标准值；单字调是孤立念出的形式，语流里的变化靠变调规则、qTA 的惯性和句子层修饰来产生。

**四、入声**

入声用三个字段表达：`checked` 为真，`dur_scale` 取短，`coda_release` 指定韵尾。喉塞韵尾用声门闭合实现。不除阻的塞音韵尾要求成阻之后不释放：闭塞保持到气压落下为止。现有爆破时序能否省去释放段而不产生多余的爆破声，需要先在引擎上验证，这也是 1.4.3 里粤语包的前置条件。

在剪辑编曲的歌唱情境下，音高由音符决定，调类表里的调值不起作用，只保留入声韵尾的处理。

**格式示例**

**实现与验收**

### 3.3 歌唱模式辅音抢拍与同构 TextGrid 迁移

**结论**：踩拍点用引擎自己知道的发音标志点来定义，不靠事后从音频里检测；前导量从两个相邻韵核之间的时间预算里倒排。同构迁移归结为一个统一操作“按区间映射重定时”，节奏迁移改时间锚点后重新合成，基频迁移把参考曲线拟合成靶点加残差，两者联动时先节奏后基频。

#### 3.3.1 现状与差距

现有 `singing.py::compile_song` 以音符起点为音节起点：字头辅音从音符起点开始发，占用音符自身的时值，韵核因此比拍点晚到一个字头的长度；相邻音高用最长 35 ms 的平滑滑音连接。原项目的歌唱规划已经写明要改为“先定韵核攻击点，再反推字头”，并给出了回归例子。所以抢拍不是重写，而是把 `_edges` 的预算对象从“当前音符”改为“相邻两个韵核之间”。

#### 3.3.2 踩拍点的定义

一个音节拆成 `字头 C* + 韵核 V + 韵尾`。踩拍点定义为韵核的声学起点，按字头类型取不同的标志点。物理模型的好处是这些时刻由调度器自己安排，是已知量：

| 字头类型 | 踩拍点对齐到 | 前导量由什么构成 |
| --- | --- | --- |
| 零声母 | 声门起振时刻 | 0，仅留 10–20 ms 的气压爬升 |
| 不送气塞音、塞擦音 | 除阻后的浊音起始（VOT 终点） | 闭塞段 + 释放 + 短 VOT，直接取现有 `stop_timing` 的标志点 |
| 送气塞音、塞擦音 | 浊音起始；可用“锚点偏置”向除阻方向前移 | 闭塞 + 释放 + 送气 |
| 擦音 | 摩擦结束、元音起振 | 摩擦段时长 |
| 鼻音、边音 | 口腔通路打开的时刻 | 鼻音或边音持续段 |
| 滑音、介音 | 向韵核过渡的中点（可调比例） | 滑音段的一部分；其余计入韵核 |

- “锚点偏置”是每个音类一个带符号的毫秒数，默认 0。它存在的原因是听感上的节拍中心并不总在浊音起始处，送气长的音尤其如此。
- 汉语介音（i、u、y）默认归入字头一侧参与抢拍，但前导量取短值；这是参数而不是硬规则，用户可以按曲风改成“介音踩拍”。
- 复元音把大部分时值留给主元音，末段才滑向韵尾；一字多音时韵尾只发一次，推到最后一个音符。这两条沿用现有实现与规划。

**外部参照**：

- “元音对拍、辅音在前”是歌声合成领域的通行约定：UTAU 的 preutterance 参数、NNSVS 沿用自 Sinsy 的 time-lag 模型、OpenUtau 的 DiffSinger 音素化器都这样处理。Sundberg 与 Bauer-Huppmann（2007）的摘要也指出，商业录音中伴奏最常与歌手的元音起点同步，提前或滞后的量在快歌里最小、慢歌里最大。该文的具体毫秒数本次没有取得全文核实。
- 节拍感知中心（P-center）的研究（Morton 等，1976）表明，听感上的节拍位置随字头而变：/ba/ 与 /ma/ 交替时，要听起来等间隔，两者的声学起点需要相差约 70 ms。这是按音类设置“锚点偏置”的依据。
- Chimera 的实现取歌唱辅音为说话时长的 0.8 倍，辅音下限 12 ms，元音下限 50 ms，可作为 3.3.3 预算参数的对照。它的对照报告测得真人歌手的起声相对音符起点为 +5 ms（元音开头）和 +18 ms（清辅音开头），而它自己的合成结果是 −15 ms 和 −24 ms。可见真人略晚于拍点而不是抢在前面，默认锚点偏置取 0 到 +15 ms 是合理的起点。该数据来自单一女歌手的英文歌曲。

#### 3.3.3 前导量的预算与压缩

对相邻两个踩拍点 `t_i`、`t_{i+1}`：

```text
可用预算   G = (t_{i+1} − t_i) − hold_min_i            # hold_min：前一韵核的最短持音，建议 max(50 ms, 音符时值的 40 %)
需求       D = coda_i 的首选时长 + onset_{i+1} 的首选时长
if D ≤ G:  全部取首选时长；多出的时间全部给前一韵核持音
elif Σ最小时长 ≤ G:  在“最小时长 ↔ 首选时长”之间按同一比例压缩（即现有 _edges 的插值）
else:      报告冲突 ScoreIssue，给出三个选项：元音晚到 / 删弱韵尾 / 延长前一音符
```

- 塞音保留已验证的闭塞、释放、VOT 标志点，只有自动生成的塞音才允许整体等比压缩到求解器下限（闭塞 10 ms、释放 1 ms），这也是现有逻辑。
- 首个音符的字头需要预备拍：工程允许负时间，或自动在开头插入预留段，并在导出信息里写明第一拍对应的采样号。
- 速度变化时辅音时长基本不随拍速缩放，只有预算不够时才压缩。所以前导量以毫秒存，不以拍存。
- 各音类的首选时长沿用现有默认（塞音 80 ms、擦音 160–180 ms、歌唱中短延迟辅音约 120 ms 封顶、一般上限 180 ms、下限 50 ms），并用下面的闭环校准按说话人修正。
- 回归测试直接采用原规划的例子：120 BPM、预留 100 ms，两个韵核应落在第 4,800 和第 28,800 个采样；第二音的 /l/ 给 80 ms，则在 0.520 s 开始。

**闭环校准，保证“稳定”**：每套说话人与构型包做一次离线校准。对每类字头合成若干 CV 音节，从输出音频测实际元音起点（低频带能量包络上升到一半的时刻，或直接取声源的起振时刻），与调度器的名义踩拍点相减，得到每类字头的系统偏差表，写入构型包。调度时扣除这个偏差。这样即使改了构型或截面数，踩拍精度也有数据可查，而不是靠耳朵猜。

#### 3.3.4 qTA 与抢拍的配合

有字头辅音时，靶点区间从字头起点开始，而不是从踩拍点开始。于是音高在辅音期间就向新音符逼近，到元音踩拍时已基本到位，前导量同时充当滑音时间（见 3.1.3 的到位时间表）。清辅音期间这段滑动听不到，只是 qTA 的隐藏状态；浊辅音和鼻音上则能听到自然的滑入。对零声母或前导量不足 50 ms 的短字头，按 3.1.3 的预滑规则把靶点切换点略提前到前一音节尾部（或提高该音符 `λ`），防止元音踩拍时才刚开始上滑。乐句首音与长休止后起音按 3.1.3 重置初值到首音符靶点。连音（同字延音）不重新起字头，只在拍点切换靶点，`λ` 可单独设置以控制滑音快慢。

#### 3.3.5 科研语音与歌唱编曲共用同一底层结构

科研工作台（自然语流分析）与剪辑工作室 `编曲`/`舞台`（歌唱定音成片）不再设置独立的左上角 `[语音 | 歌唱]` 模式开关，两者的差异仅仅取决于调度上下文与乐谱音符轨是否存在，音节、音段、靶点、关键帧与 `PHON` 离散发声态锚点的数据结构完全相同：

| 项目 | 科研语流情境（科研工作台） | 歌唱编曲情境（剪辑工作室） |
| --- | --- | --- |
| 时间来源 | 时长模型（音类默认时长、重音与边界延长） | 乐谱的拍与速度图（`BPM`） |
| 音节锚点 | 音节起点 | 韵核起点对齐拍点，字头前置 |
| 靶点区间 | 音节 | 音符（支持一字多音简谱 `(3//5//)`） |
| 默认靶点 | 词调与语调规则 | 音符音高，可选保留部分调形 |
| `λ` 默认 | 较低，允许自然协同不到位 | 较高，要求踩拍到位 |
| 韵核 | 按协同发音自然过渡 | 显式持音区，末段才归韵 |
| 微扰默认 | flutter 较明显 | flutter 降低，另有颤音 |
| TextGrid | 音节层（右下角 `◢` 切多音字）、单音素层 | 另加“音符层”，边界在拍点上；音节层边界在字头起点上 |

工作区之间的跨屏切换与 `.vcproj` 拖放直接实时联动生效，无需打断用户的「切换模式确认弹窗」，一切手工关键帧、手绘 F0、离散发声态锚点均按音节与音素 ID 持久化保留并入统一撤销栈。

#### 3.3.6 同构 TextGrid 迁移

**前置校验**：两份 TextGrid 所选层的区间数相同、标签逐一相同（忽略首尾空白，静音标签按等价集合处理）。不一致时列出第一个差异位置并拒绝执行，不做猜测性对齐。用户选择用哪一层做锚点：节奏建议用音段层，基频建议用音节层。

设源区间边界为 `a_0 < a_1 < … < a_n`，参考为 `b_0 < b_1 < … < b_n`。

**① 仅迁移节奏**。目标是源的每个区间时长变成参考的时长，内容、音高走向不变。

- 对合成素材和反演素材，不拉伸音频，而是重定时控制数据后重新合成。
- 区间内不能均匀拉伸，否则塞音爆破、过渡段会被拉长失真。把区间内的时间分成两类：
  - 刚性段：闭塞释放、送气与 VOT、CV 与 VC 过渡斜坡（封顶）、颤音周期。保持原时长，贴靠在它所依附的边界上。
  - 弹性段：元音稳态、擦音稳态、鼻音持续、闭塞保持、静音。吸收全部伸缩。
- 区间内的时间映射是分段线性的：刚性段斜率为 1，弹性段斜率为 `k = (新时长 − 刚性总长) / 弹性总长`。新时长小于刚性总长时，刚性段等比压缩到求解器下限并给出警告，仍放不下则该区间标红。
- 各轨处理：
  - 稀疏关键帧：只换算时刻，构型不变。
  - 反演得到的密轨：按上述映射换算每帧时刻，再以引擎控制周期重采样（逐参数 PCHIP）。
  - 基频：不拉伸曲线样本。靶点区间跟着新边界走，动态靶点保持总升降幅度不变（`m' = m·D/D'`），然后重跑 qTA；残差与钉住片段按归一化坐标自动跟随。
  - 气压包络、区段特征：同样按归一化坐标跟随。
- 对原始录音素材（用户要保留真人音色），用同一张映射表做时长变换，交给现有变速变调模块处理，瞬态段按刚性段保护。

**② 仅迁移基频**。目标是保持源的时间不动，把参考的基频走向搬过来。

- 提取参考 F0（桌面已有 SwiftF0），做倍频跳变修正与中值滤波，在对数域跨清音段插值，得到连续曲线。现有反演链把 SwiftF0 的范围设为 65–350 Hz，参考音是女声高音或花腔时需要放宽上限，否则高音段会被判为缺测。
- 逐区间按归一化时间搬运：源区间 `i` 内时刻 `t` 取参考区间 `i` 内相同相对位置的值。
- 音域处理三选一：绝对（照搬 Hz）、相对中值（各自减去说话人中值后搬运半音偏移，默认）、相对中值并按音域跨度缩放。
- 写入方式：按 3.1.4 的方法对每个靶点区间拟合 `(m, b, λ)`，写为 `transfer` 来源的靶点；拟合剩余的差值存为残差片段，并提供“残差保留比例”滑块，0 为纯 qTA 风格化，1 为逐点复制。需要逐点精确时可改写为钉住。
- 是否发声由源的音段内容决定，参考的清浊判断不搬运。

**③ 两者联动**。先执行 ①，使源的边界与参考完全重合；此时时间映射为恒等，再执行 ②，参考 F0 只被采样一次，靶点拟合直接在最终时长上进行，不需要换算斜率。两步打包成一个事务，撤销一次即全部还原。

三种迁移在命令层是同一条指令 `transfer.apply(source, reference, what = rhythm | f0 | both, options)`，输出是一份可预览、可撤销的补丁。2.5 节的“三轨时间锁定”在拖动单个边界时执行的是同一个重定时函数，只是映射表里只有一个边界发生变化。

### 3.4 自动关键帧检测、局部改帧重插值与连续统对齐

**结论**：关键帧检测用联合判据，三类指标各管一类问题：构型速度极小点找“到位的姿态”，截面积阈值事件找“成阻与除阻”，TextGrid 边界负责命名和保证每个音段至少有一帧。然后用误差受限的精简把候选压到最少。改帧时改的是“相对原密轨的差值”，连续统在标志点对齐后的任务空间里插值，阻塞音的狭窄度单独保护。

#### 3.4.1 现状

- 原项目桌面反演是“候选库 + 38 带模板 + Viterbi 解码 + 共振峰细调”：JD2 约 135 个、W02 约 111 个候选构型，12.5 ms 一帧，耗时高（1.4 秒短句 CPU 并行约 36 秒）。
- 另已在独立工程 `F:\TensorTract3_Train` 训练完成端到端神经反演 **TensorTract3（M10 R21 + JD2）**：以冻结 `WavLM-large`（315 M 参数，~1.18 GB）作特征提取，接 9.01 M 的 `MotorEncoder`（`T24` 模式，只用第 24 层）和 3.21 M 的 `PressureEncoder`（25 层加权和）以及 0.13 MB `SwiftF0 0.3.0`，以 50 Hz 帧率直接预测 20 维归一化声道/声门控制（`m20`）+ 肺压（`PR`）+ `F0`，升频至 200 Hz 驱动 R21 合成 48 kHz 波形，GPU 单句推理仅 ~0.1 秒。
- 反演子进程已有 `revise()`：锚点编辑加平滑。二重唱规划也写明了“在邻近帧的原始轨迹上叠加平滑衰减的差值，默认不跨静音、缺测或锁定的成阻与释放边界”。
- 轨迹插值在 `trajectory.py`（共享速度的三次 Hermite、smoothstep），协同发音在 `coarticulation.py`（含 `constriction_guard` 保护狭窄点），引擎可给出 `oral_min_area`、`constriction_sections`、面积函数与共振峰。

这些足以支撑下面的方案，不需要新的原生接口。

#### 3.4.2 自动关键帧检测

**步骤一：预处理**。按音段分段平滑（Savitzky–Golay 或 RTS 平滑均可），平滑不跨静音与闭塞边界。把 19 个参数加舌形、唇形附加量各自按取值范围归一化。

**步骤二：换到任务空间算速度**。原始参数量纲不一，而且对声音的影响差别很大。除归一化参数外，再取几条由引擎直接给出的任务量：口腔最小截面积及其位置、唇开度、腭咽口面积、声门状态。速度定义为加权范数 `v(t) = ‖W · d/dt [参数; 任务量]‖`，权重默认让“形成狭窄的发音器官”占主导。

**步骤三：三类候选**。

| 判据 | 找到什么 | 作用 | 备注 |
| --- | --- | --- | --- |
| 速度局部极小且低于阈值 | 姿态到位点（元音、响音的目标） | 关键帧主体 | 取极小点处的构型作为该帧姿态 |
| 最小截面积穿越阈值 | 闭塞形成、除阻、进入或离开摩擦临界区；腭咽口开闭；声门启闭 | 强制关键帧 | 这类事件决定音类，哪怕速度很大也必须落帧；塞音直接生成 `stop_timing` 标志点而不是普通帧 |
| TextGrid 音段边界 | 音段归属 | 命名与兜底 | 每个音段保证至少一帧（取离音段中心最近的速度极小点）；边界本身一般不落帧 |

加速度过零点对应速度峰值，也就是过渡的中点，它不适合做关键帧，但适合在没有 TextGrid 时作为“候选边界”提示给用户确认。反演输出的候选路径 `path` 还提供了一个便宜的初值：同一候选连续出现的区段大致对应一个稳定姿态，区段切换处对应过渡。实际能否直接使用取决于路径的稳定程度，建议先用它做初筛，再用速度判据校正。

**步骤四：误差受限精简**。从强制关键帧出发，用产品自己的插值核重建轨迹，在重建误差最大处插入下一帧，直到最大误差低于容差。误差在声学相关的量上度量（面积函数的对数差，或引擎传递函数给出的前三个共振峰偏差），不在原始参数上度量。界面只暴露一个“精度/密度”滑块。这一步保证了一个用户真正关心的性质：稀疏关键帧重建出来的声音与反演密轨足够接近。

**步骤五：保留细节层**。原密轨不丢弃，存为该片段的只读参考层，同时保存 `细节 = 原密轨 − 关键帧重建`。播放用 `关键帧重建 + 细节`，所以自动提帧本身不改变声音；用户随后的编辑只改关键帧层。A/B 对照轨里的“反演初稿”就是这一层。

#### 3.4.3 改单帧后的重插值

1. 用户在悬浮小窗里拖动器官，得到该帧的差值 `Δ`。
2. 影响范围默认到前后相邻关键帧，权重 `w(t)` 在本帧为 1、在相邻帧为 0，用五次 smoothstep 保证位置、速度、加速度在两端连续。结果为 `新轨迹 = 原轨迹 + w(t)·Δ`，相邻帧的姿态完全不变。
3. 可以只对选中的器官生效（只改舌尖不动下颌），其余参数的差值为零。
4. 传播在以下位置截断：静音、缺测帧、被锁定的闭塞与释放标志点。塞音的时序由 `stop_timing` 管，不由插值管。
5. 重插值之后做一次“构型检查”：沿被影响的区间逐控制帧取最小截面积，对比编辑前后。出现两种情况时标记并给出一键修复：
   - 意外闭塞：两端都不是闭塞，中间却出现了面积趋零（参数线性过渡时舌体扫过上腭）。修复方式是插入一个辅助帧，沿下颌或舌高方向让开。
   - 闭塞丢失：原来的闭塞或摩擦狭窄被差值冲开。修复方式是把该帧的狭窄度投影回原类别。
6. 只重新合成受影响的时间范围，前后各带一小段预滚以保持声源与声管状态连续。原项目的区间试听已说明“片段起点重新初始化声源与声管，不承诺与整段输出逐样本相同”，因此局部试听用于判断，定稿导出仍按乐句整段渲染。

#### 3.4.4 “庄 → 张”连续统

两个音节的差别在介音：/ʈʂwɑŋ/ 比 /ʈʂɑŋ/ 多一个 /w/（圆唇加舌根抬高），声母、韵腹、韵尾和声调相同。音段数不同，时长也可能不同，不能按时间直接线性混合。

**第一步：结构对齐**。把两个音节都展开成同一张标志点表：闭塞起点、除阻、摩擦结束与浊音起始、介音目标、韵腹目标、韵尾目标（软腭闭合、腭咽口打开）、音节终点。“张”没有介音，就插入一个零强度的虚拟标志点，其构型取“张”自身轨迹在对应相对位置上的值。这样两边标志点一一对应。

**第二步：时间对齐**。以标志点做分段线性的时间配准，把两条轨迹都映射到公共的归一化时间 `τ` 上。这一步是确定性的，研究者能说清每一帧对的是什么。需要更细时可在相邻标志点之间再加一次受约束的 DTW。

**第三步：分别插值时间和形状**。

```text
标志点时刻   T_k(α) = (1 − α)·T_k^A + α·T_k^B          # 可选“时长等化”：所有步使用同一组时刻，排除时长线索
构型         P(τ; α) = (1 − α)·P_A(τ) + α·P_B(τ)        # 仅对标记为“参与变化”的槽位和器官生效
α = (i − 1) / (N − 1),  i = 1 … N                      # 9 步时 α = 0, 0.125, …, 1
```

**第四步：阻塞音与擦音保护**。这是防止中间帧物理失真的关键，按槽位分类处理：

| 两端在该槽位的关系 | 处理 | 说明 |
| --- | --- | --- |
| 完全相同（本例的声母 /ʈʂ/） | 锁定，不参与插值，直接取 A 的轨迹 | 中间步的闭塞、除阻、摩擦与两端逐帧一致 |
| 同部位同方式，程度不同 | 在任务空间插值：先线性混合构型，再沿狭窄度方向做一维修正，使最小截面积等于两端面积的插值 | 闭塞保持完全闭合，摩擦保持在临界面积内 |
| 同器官、部位不同（如 t 与 ʈ） | 插值狭窄位置，狭窄度保持类别值 | 物理上有效的连续滑动 |
| 方式不同（塞音与擦音） | 在对数面积上插值，并提供非均匀步长，在类别边界附近加密 | 感知上本来就是突变，如实告知 |
| 发音器官不同（如 p 与 t） | 不同时混合两个闭塞。以 α = 0.5 为界，主导手势保持完全闭塞，另一手势以渐变的幅度作为次要调音 | 生理空间里没有“半个 p 半个 t”的塞音，这是物理限制；需要平滑的声学连续统时改用现有的 Klatt 参数连续统 |

塞音的闭塞时长、释放时长、VOT 作为标志点时刻参与第三步的时间插值，所以 VOT 连续统天然支持。

**第五步：逐步检查与批量合成**。每一步合成前跑与 3.4.3 相同的构型检查，并额外核对：闭塞帧面积为零，摩擦帧面积在临界区间内，鼻音帧腭咽口打开。不通过的步在清单里标红，不静默输出。全部步使用相同的随机种子、相同的基频靶点和气压包络。

**二维矩阵与导出**。第二个维度可以是基频（两组 qTA 靶点之间插值 `m、b`，例如阴平到阳平）或发声（声门预设之间插值，例如正常嗓音到气声）。两个维度正交组合成 `N × M` 个刺激。导出包包含：

- 每个刺激的 WAV（原始电平）以及可选的响度归一化副本。归一化会抹掉强度线索，所以两份都给，由研究者选择。
- 每个刺激的逐帧构型与面积函数、控制基频、TextGrid。
- 一份清单 `manifest.json`：每个刺激在各维度上的步号与 `α`、被锁定与参与变化的槽位、说话人与几何版本、截面数、引擎与方法版本、随机种子、采样率、时长等化与归一化选项。
- 可选直接生成现有感知实验模块能读取的实验配置。

文件命名形如 `zhuang-zhang_a05of09_f03of07.wav`，清单是唯一权威来源，文件名只为方便人看。

#### 3.4.5 TensorTract3 神经反演部署、双轻量蒸馏与 Neural Re-synthesis 演进

**问题本质**：TensorTract3 中真正训练得到的构音大脑非常轻（`MotorEncoder` 9.01 M + `PressureEncoder` 3.21 M + `SwiftF0` 0.13 MB，去掉优化器后纯 FP16 权重仅 **~24.5 MB**，INT8 仅 **~12.3 MB**）。1.18 GB 体积全部来自上游公共底座 `WavLM-large`（315 M），且因 `MotorEncoder` 采用 `T24` 模式（依赖第 24 层特征），无法在不重训的前提下裁剪后半段层。绝不能要求普通用户下载 1.18 GB 底座。

**三档递进方案**（前端统一调用 `inversion.predict(audio)`，随时切换后端，界面代码零改动）：

| 形态 | 模型组成与体积 | 推理位置 | 是否重训 | 适用阶段与场景 |
| --- | --- | --- | --- | --- |
| **云端极薄 API（黑客松立即可用）** | `WavLM-large (FP16)` + 纯权重 `MotorEncoder (18 MB)` + `PressureEncoder (6.4 MB)` + `SwiftF0 (0.13 MB)`；显存 ~1 GB | 云端按需 GPU（阿里云 FC / 弹性 GPU / 魔搭创空间）或 CPU ONNX INT8（~330 MB） | 否 | **黑客松 & 公测**。前端只传压缩 16 kHz 音频（10 s 约 40–150 KB），云端返回 50 Hz `m20+PR+F0` 轨迹（10 s 仅 ~44 KB），声道渲染与编辑仍在用户本地 VTL Wasm 完成；按音频 SHA-256 缓存结果 |
| **极轻浏览器蒸馏版** | 80 维 Log-Mel（50 Hz）+ 轻量 Conv2d 前端 + Conformer(8 层, 192 维) + BiLSTM；**FP16 ~20 MB，ONNX INT8 ~10–15 MB** | 浏览器本地 `onnxruntime-web`（WebGPU / Wasm），零服务器成本 | 单阶段监督蒸馏 | **赛后 Web / 移动端常驻**。5 秒音频浏览器本地 < 0.5 秒 |
| **高精度轻量蒸馏版** | 冻结 `WavLM-base-plus`（95 M）或前 9 层 + 轻量回归头；**ONNX INT8 ~80–110 MB** | 桌面端按需离线包或低成本 CPU 云主机 | 单阶段监督蒸馏 | **赛后桌面离线 / 科研高精度反演**。跨说话人泛化逼近 large，体积缩小约 12 倍 |

**为什么蒸馏不需要重跑 4 阶段训练，且数据已经齐备**：
- 原始 Stage 1–4 依赖 `WavLM-large` 与 `AcousticDecoder`，是为了在自然语音缺乏真值构型时弥合“真人音色 vs VTL 合成音”的表征鸿沟。如今老师模型（`motor_natural + pr_encoder`）已经训通，可以直接对无标注自然语音前向产出 50 Hz 连续软标签（`m20 + PR`）。
- 两个轻量学生版只需要**单阶段 L1/MSE 监督蒸馏**：复用现成 `F:\TensorTract3_Train\data\synth_100h`（90 h 物理真值，锚定物理可解释性）+ 用老师模型对 `F:\KeSpeech`、`F:\LibriSpeech` 与单音节语料抽 50–100 h 跑出伪标签缓存（100 h float16 轨迹仅 ~750 MB；若扩展歌唱反演可混入 5–20 h 无伴奏开源清唱）。在现有 RTX 5090 Laptop 24 GB 上，打伪标签约 1–2 小时，极轻浏览器版训练约 1–3 小时，高精度轻量版约 3–6 小时。

**与 Neural Re-synthesis（神经重合成）的协同**：
- 若后续继续训练 **Re-synthesis (Neural) 版**：
  - 若指**用神经重合成闭环进一步增强反演老师模型**，建议先完成老师模型升级，再统一蒸馏两个轻量学生版，学生即可继承全部精度提升。
  - 若指**训练神经声码器（`m20 + PR + F0` → 高自然度音频波形）**作为 VTL 物理输出之外的可选“神经音质通道”，该声码器天生不依赖 `WavLM-large`（输入仅 50 Hz × 22 维），选用 `Vocos` / `iSTFTNet` 等轻量架构本身仅 **6–26 MB（FP16）/ 3–13 MB（INT8）**，可同步产出桌面高精度版与浏览器极轻版；所需数据为“干净单说话人语音 + 对应控制轨”配对（先用 `synth_100h` 预训，再用单人高质量语料 10–30 h 配老师反演轨微调音质）。
- 科研可信度边界不变：无论 VTL 还是神经反演/神经重合成，界面与导出元数据均标明“反演轨迹为模型候选解释，非实测舌位；神经重合成音为声码器渲染，与物理管段输出分开标识”。

### 3.5 60 fps 多图层渲染管线与 AI 工程 DSL 安全边界

**结论**：工程文件只存“意图”，不存可重算的结果；所有修改，不论来自鼠标、脚本还是 AI，都走同一条命令总线，每条命令产生一对正向与逆向补丁。固定脚本出片就是“模板工程 + 输入表”在无界面模式下跑同一条编译与渲染管线。AI 的安全边界靠四件事：只能调用登记过的命令、越界即拒绝并返回合法范围、先预演后提交、整个提案作为一步撤销。

#### 3.5.1 工程文件的三层

```text
project.vcproj/                  # 目录或 zip；便携交换时打成单文件
├─ project.json                  # 声明式工程：唯一事实来源，可人读、可 diff
├─ assets/<sha256 前缀>/…        # 原始素材，按内容摘要寻址：录音、BGM、图片、字体、TextGrid、乐谱
├─ oplog.jsonl                   # 命令日志：撤销重做与 AI 提案审计
└─ cache/                        # 可随时删除：PCM、状态轨、视频帧、波形缩略
```

| 层 | 内容 | 是否入工程 | 说明 |
| --- | --- | --- | --- |
| 意图层 | 歌词、乐谱、IPA、靶点、关键帧、覆盖项、图层与关键帧、样式 | 是 | 用户和 AI 编辑的对象 |
| 编译层 | 调度后的时间锚点、控制帧序列、TextGrid | 可重建，按需导出 | 由意图层确定性生成 |
| 渲染层 | PCM、逐帧声道状态、视频帧 | 否，放缓存 | 缓存键 = 输入内容摘要 + 引擎与几何版本 + 截面数 + 种子 |

这延续了原项目已经在做的事：内容摘要去重、48 kHz 整数采样与半开区间、种子随文件保存、便携工程校验 SHA-256。新增的是把现在分散在 `.ptb-vocal.json`、`.ptb-duet`、`.ptbi.json` 和外部 `scene.mjs` 里的内容收进同一个 Schema。

设计要点：

- **稳定 ID 与字典索引**。核心实体集合（`clips`、`syllables`、`layers` 等）采用“按不可变 ID 索引的对象字典 + 独立 `*_order` 顺序数组”，绝不用数组下标引用对象。这样 AI 在第 3 轮提到的 `sy_0003` 到第 10 轮仍是同一个字，同时 3.5.4 的标准 RFC 6902 JSON Patch 路径 `/clips/cl_v1/syllables/sy_0003/...` 也能严格合法执行。
- **单位写进字段名**（`_smp`、`_ms`、`_st`、`_hz`、`_pa`、`_cm`）。原项目气压在引擎里是 dPa、界面是 Pa，这类换算只允许发生在引擎适配层。
- **时间有三种写法，各司其职**：乐谱用 tick，绑定节拍的视觉关键帧用小节与拍，绝对位置用整数采样。60 fps 时每帧正好 800 个采样，30 fps 为 1,600，24、25、50 fps 也都是整数，帧与采样之间没有舍入误差。
- **覆盖项挂在音节上**，并使用归一化坐标 `u`。上游的歌词、乐谱或调度策略改了以后重新编译，下游的手工微调按音节 ID 重新挂接；挂不上的进入“孤立覆盖项”列表，由用户决定丢弃还是改挂。这解决了原规划里提到的“重配一个音符丢失整句实验”的问题。
- **没有表达式，没有脚本执行**。工程文件是纯数据。缓动函数、绑定类型、图层种类都是枚举值。模板里的占位符只做整值替换。

#### 3.5.3 作为固定脚本出片模板

模板就是一份 `inputs` 未填的工程，加上一张输入表：

```jsonc
// inputs.json
{ "lyrics": "lyrics.txt", "score": "song.jianpu", "bgm": "bgm.flac",
  "characters": ["a.png", "b.png"], "background": "bg.png", "voice": "W02" }
```

```text
vocalcut render --template neon-duet.vctpl --inputs inputs.json --out out.mp4
```

无界面入口执行与界面完全相同的五步：读入并校验、编译（G2P、调度、靶点）、合成（按乐句、带缓存）、逐帧绘制、封装。原项目的 `session.Runtime.invoke` 与 `animation.prepare_animation` 已经是不依赖界面的调用面，加命令行入口的成本较低；目前仓库里没有找到面向用户的命令行合成入口，需要新写。

#### 3.5.4 命令总线与撤销

原项目现在有四套互不相通的撤销（二重唱编辑器的快照栈、声道页的 history、基频页每模式 50 步、关键帧页的零星撤销）。新架构只保留一套：

```jsonc
// 一条命令
{ "op": "artic.set_pose_delta", "base_revision": 128,
  "args": { "syllable": "sy_0003", "seg": 2, "delta": { "TCY": -0.25 }, "scope": ["tongue_body"] } }

// 执行结果
{ "ok": true, "revision": 129,
  "patch":   [{ "op": "add",    "path": "/clips/cl_v1/syllables/sy_0003/overrides/poses/-", "value": { … } }],
  "inverse": [{ "op": "remove", "path": "/clips/cl_v1/syllables/sy_0003/overrides/poses/0" }],
  "dirty":   { "audio": [["cl_v1", 91200, 124800]], "video": [1140, 1560] },
  "warnings": [] }
```

- 命令是语义化的（“给这个音节的韵腹加一个构型差值”），不是任意 JSON 路径写入。补丁格式采用 JSON Patch，只作为命令的产物出现，外部不能直接提交补丁。
- 每条命令先过 Schema 校验，再过语义校验（参数范围、IPA 是否在当前构型包里、时间顺序、ID 是否存在、3.4.3 的构型检查），最后才落盘并写入日志。
- `base_revision` 做乐观并发：AI 基于旧版本提出的命令在用户已手动改动后会被拒绝并要求重读，不会覆盖用户刚做的修改。
- `dirty` 给出受影响的音频区间和视频帧区间，缓存只失效这一部分。
- 事务：若干命令可包成一个事务，作为撤销栈里的一步。

#### 3.5.5 AI 调用的安全边界

| 约束 | 做法 |
| --- | --- |
| 能力白名单 | AI 只能调用第 4 章登记的工具。工具清单、参数范围、IPA 合法集都从同一份登记表自动生成，说明书与代码不会各说各话 |
| 不静默夹紧 | 越界参数直接拒绝，错误体里带合法范围和最近的合法值，让模型自己改正。这与原项目“超范围音名明确拒绝”的约定一致 |
| 先预演后提交 | AI 的修改先进入提案事务：在工程副本上执行，返回差异摘要、构型检查结果和受影响区间的试听。用户点接受才合并到主工程 |
| 一步撤销 | 一个提案无论包含多少条命令，都是撤销栈里的一步；提案的原始对话、命令与补丁写入日志，可事后审计 |
| 三级权限 | 只读工具自由调用；编辑工具走提案；有外部副作用的工具（导出文件、删除素材、联网）每次都要用户确认 |
| 文件边界 | AI 只能引用素材 ID 和用户已授权的目录，不能给出任意路径。延续原项目的目录授权机制 |
| 预算 | 单个提案的命令数、可触发的合成时长、单轮对话的工具调用次数都有上限，超限需要用户放行 |
| 内容即数据 | 歌词、TextGrid 标签、方言包 CSV、乐谱图片里的文字一律当数据处理。工具返回值里明确标注来源，导入内容中的“请执行某操作”不构成指令 |
| 确定性 | AI 只产生命令，不参与渲染。同一份工程在同一引擎版本上合成结果逐采样一致，与是谁写的命令无关 |

规则说明书不整本塞进上下文。系统提示里放一份由登记表生成的精简版（工具目录、单位约定、核心取值范围、工作流程），细节通过只读工具 `rules.get(topic)` 按需取，例如某个构型包的 IPA 清单或各声门预设的参数。这样既不挤占上下文，也保证 AI 看到的规则永远是当前版本。

#### 3.5.6 60 fps 多图层渲染管线

原项目已经验证过 1080p、60 fps、7,920 帧的整片导出，两次独立渲染音频流哈希相同、画面 SSIM 0.998。新管线把这条路径固化并把外部脚本里的图层收编进来。

```text
帧号 k ──▶ 采样号 800·k ──▶ 场景求值（纯函数）──▶ 分层绘制 ──▶ 编码 ──▶ 封装
                              │
                              ├─ 背景、图片与立绘（图集 + 切换点）、几何形状
                              ├─ 声道层：从状态轨取相邻两帧姿态，按对应轮廓点插值
                              ├─ 物理量叠加层：面积函数、共振峰、控制基频、气压、狭窄高亮、洋葱皮
                              ├─ 频谱层：混音预先算好的逐帧频带能量
                              ├─ 粒子层：带种子，位置是帧号的闭式函数
                              └─ 字幕与 IPA 层：逐字显现、倾角、变色，安全边距
```

- **预览与导出同源**。场景求值只依赖工程和帧号，不读系统时钟，不调用无种子的随机数。预览和导出走同一套绘制代码，差别只在分辨率和是否跳帧。
- **声道状态轨**。合成时以固定显示帧率记录姿态快照（现为 30 fps），60 fps 导出在相邻快照之间插值。原项目验收里已注明“中间帧为可视化插值”，界面和导出信息里保留这句说明。需要严格逐帧真实姿态时，把快照率提高到 60 fps，代价是缓存翻倍。
- **粒子用闭式而不是逐帧积分**。每个粒子的位置由 `(种子, 出生帧, 当前帧)` 直接算出，可以从任意帧开始渲染、任意分段并行，结果一致。
- **字幕与 IPA**。沿用《人是猫》修订版验证过的做法：用 Doulos SIL 以完整字符串一次排版，先旋转再测量完整像素边界，按整行选字号并居中，逐个显现位置做透明边界检查。安全边距在 Schema 里声明，导出前自动检查所有字幕帧是否越界，上下叠加的附加符号按实际墨迹边界算。
- **编码**。页面内用 WebCodecs 编码，只有压缩后的数据离开页面，避免把每帧约 8 MB 的原始像素搬过进程边界。Web Wasm 路线下，可直接前端输出 WebM（VP8 + Opus），或使用 WebCodecs H.264/AAC 配合纯 JS 封装库（如 `mp4-muxer`）在浏览器内直接产出标准 MP4，无需服务端转码；桌面端交付 MP4 时可复用后端 PyAV 与 FFmpeg。原验收发现过一次颜色范围问题（全范围数据被按视频范围解释导致偏暗），编码与封装参数里必须显式写明输入全范围、输出标准范围与 BT.709，并保留“抽帧对比预览”的自动检查。
- **长曲分块**。单次序列上限为 60 秒。整首歌按乐句在休止处切块，各块独立合成后按绝对采样号拼接；无停顿的连音不跨块。视频帧可分段并行绘制。
- **物理量显示的边界**。当前 `vtlSynthesisAddTube` 逐帧合成路径只输出音频、面积函数、传递函数与共振峰，不暴露每步的腔内气压分布、气流速度和声门面积波形（注：VTL 2.4 的 `vtlGesturalScoreToAudio` 原生支持通过 `miscFileName` 参数导出每时间步的声门气流与气压，但本产品走逐帧管段合成而非 `.ges` 路径）。要在逐帧路径里显示这些量，需要给原生桥接层打补丁增加状态导出（该层为 GPL，补丁需同样开源）。在此之前：面积函数、共振峰、控制基频、声门下压包络、基于最小截面积的“狭窄处高亮”可以如实显示；气流箭头和压力色带只能作为示意，并在界面上标注“示意，非计算值”。原项目的歌唱规划里已有同样的原则。

## 4. AI 对话控制接口：Tool Calling 指令清单

### 4.1 协议约定（双通道 AI 路由与安全边界）

- **知乎直答接口实测边界与双通道 AI 路由**：经官方 `http-api.md` 核实，知乎直答 `POST https://developer.zhihu.com/v1/chat/completions`（`zhida-fast-1p5` / `zhida-thinking-1p5` / `zhida-agent`）**可以真实接入**（服务端 `Authorization: Bearer <ZHIHU_ACCESS_SECRET>` + `X-Request-Timestamp`，支持 SSE `stream=true`）。但该接口**官方仅保证 `model / messages / stream` 三个请求字段能力语义**（`zhida-agent` 仅单轮上下文），不正式保证原生 OpenAI `tools[]` 函数调用与多模态 `image_url` 图片载荷，且配额上限为 **`100 次/天`**（超限返 `30001`）。因此架构明确采取**双通道路由**：
  - **Channel A · 知乎直答通道**：承担首页刘看山科普速问、知乎语境搜索综述与理论问答；若用户在知乎直答通道下达调音指令，系统通过严格受控系统提示词要求其返回「解说文本 + Schema JSON 提案块」，由前端解析器提取后照常交由命令总线校验并生成提案卡片。
  - **Channel B · `tools[]` 与视觉审片执行通道**：复用 OpenAI 兼容的 Chat Completions 工具调用与 `image_url` 多模态格式接入 `.env` 中的外部推理/视觉大模型（默认可在 DeepSeek/Qwen 等模型间配置，密钥仅存服务端代理，严禁入前端），负责高精度 `tools[]` 函数编排、多步自动化 `analysis.*` 闭环及 `preview.contact_sheet` 视觉审片；原项目文档助手仅作问答参考，全部参数工具层为本工程新做。
- **三级权限**：R 只读，自由调用；E 编辑，进入提案事务，用户接受后生效；X 有外部副作用，每次调用都要用户确认。
- **统一返回**：

```jsonc
// 成功
{ "ok": true, "revision": 131, "result": { … }, "warnings": [{ "code": "pose_lint.unintended_closure", "at": "sy_0012" }] }
// 失败：不夹紧，告诉模型合法范围
{ "ok": false, "error": { "code": "out_of_range", "field": "args.note_hz", "value": 660,
    "allowed": { "min": 60, "max": 600, "unit": "Hz" }, "hint": "最高可用音为 D5（587.3 Hz）；可整体降调或改用更高音域的说话人" } }
```

- **引用方式**：对象一律用 ID；时间可以写采样号、秒、`{bar, beat}`，或 `{syllable: "sy_0003", u: 0.8}`。工具返回里总是带上解析后的采样号。
- **AI 听不见声音**。所有“听感”判断都要落到 `analysis.*` 返回的数值上，最终由用户试听裁决。提案审阅界面必须提供修改前后的 A/B 试听。

### 4.3 四类工作流

**① 多模态读谱与填轨**

1. 用户发来乐谱（图片、文本简谱或 MusicXML）与歌词。MusicXML 和文本简谱由程序直接解析，不经过模型；图片由多模态模型识别。
2. 模型输出结构化乐谱，调用 `score.validate`。

```jsonc
{ "time_signature": [4, 4], "bpm": 96, "key": "C", "pickup_beats": 0,
  "voice": "vo_a", "transpose_st": 0,
  "measures": [
    { "n": 1, "events": [
      { "type": "note", "pitch": "E4", "beats": 1,   "lyric": "好", "tie": false },
      { "type": "note", "pitch": "E4", "beats": 0.5, "lyric": "一" },
      { "type": "note", "pitch": "G4", "beats": 0.5, "lyric": "朵" },
      { "type": "note", "pitch": "A4", "beats": 0.5, "lyric": "美" },
      { "type": "note", "pitch": "C5", "beats": 0.5, "lyric": null, "melisma": true },
      { "type": "note", "pitch": "A4", "beats": 0.5, "lyric": "丽" },
      { "type": "note", "pitch": "G4", "beats": 0.5, "lyric": "的" } ] } ],
  "uncertain": [{ "measure": 3, "reason": "高音点模糊，可能是 5 或高八度 5" }] }
```

3. 校验不过（某小节时值合计不等于拍号、歌词数与非延音音符数不等、音高超出 60–600 Hz）时，模型根据错误自行修正；修不了或者自己标了 `uncertain` 的地方，向用户提问。
4. 界面显示“读谱校对”视图：原图与识别结果并排，逐小节可改。用户确认后才调用 `score.apply`。
5. `score.apply` 一次完成：歌词转 IPA、音节计划、抢拍调度、音符层与音节层 TextGrid、qTA 靶点、默认气压包络与长音颤音。返回调度冲突清单（例如“第 7 小节‘spring’前导量不足，已压缩到 62 %”）。

图片读谱的错误率不会是零，简谱里的高低音点、减时线、附点很小，最容易错。校验规则和校对视图是这条工作流能用的前提，不能省。

**② 诊断与定点调音**

1. 用户说：“第 12 秒那个塞音太闷。”
2. 模型调用 `timeline.query` 定位到具体音节与音段，`analysis.measure` 取闭塞时长、释放时长、VOT、除阻前气压、最小截面积轨迹，`rules.get("diagnosis")` 取诊断对照表。
3. 模型按对照表提出修改，调用编辑工具，再 `preview.render` 取修改后的测量值做对比。
4. 界面显示提案：改了什么、测量值前后对比、A/B 试听。用户接受或拒绝。

诊断对照表是规则登记表的一部分，首版先覆盖最常见的反馈：

| 用户说法 | 先测什么 | 常见处置 |
| --- | --- | --- |
| 塞音太闷、不脆 | 闭塞是否完全（面积是否为零）、释放时长、除阻前气压、VOT | 缩短释放；除阻前抬高气压包络；送气音加长送气；检查后接元音的过渡是否过慢 |
| 尾音改成轻柔气声 | 该音节末段的声门预设与气压 | 末段向 `breathy` 预设渐变混合；气压包络缓降；可略增 flutter |
| 鼻音太重 | 元音段腭咽口面积 | 降低邻接元音帧的腭咽口开度；减弱鼻音对元音的协同发音强度 |
| 咬字不清 | 擦音最小截面积是否在临界区、辅音时长、协同发音强度 | 提高辅音强度；加长前导量；把狭窄度拉回临界区 |
| 没踩在拍上 | 实测元音起点与拍点的偏差 | 调前导量或锚点偏置；检查是否被预算压缩 |
| 跑调、滑音太慢 | 实测 F0 与靶点的差、到位时间 | 提高 `λ`；加长前导量；检查是否触发变调超速 |
| 太机械 | flutter、气压包络是否恒定、长音是否无颤音 | 增加 flutter；按乐句画气压起伏；长音加颤音 |
| 声音太紧或太虚 | 声门预设、气压 | 在 `pressed`、`modal`、`breathy` 之间调整混合比例 |

这张表是工程经验的起点，不是语音学定论。每条处置都限定了可改的参数和幅度上限，模型不能在表外自由发挥到其他参数上。

**③ 科研连续统批处理**

用户说：“做‘庄’到‘张’的 9 步连续统，阴平，再乘上阴平到阳平 7 步，时长等化，导出给感知实验用。”模型调用 `text.to_ipa` 取两个音节，`continuum.create` 建任务（返回对齐后的标志点表、被锁定与参与变化的槽位、每步构型检查结果），向用户展示摘要，确认后调用 `export.stimuli`。模型在这里的价值是把自然语言翻译成一份完整、无遗漏的任务配置，并解释对齐和锁定的含义；计算全部由确定性的内核完成。

**④ MV 视觉导演**

用户给出素材与风格描述。模型调用 `scene.apply_template` 选模板并填入背景、立绘、配色；`visual.set_keys` 按段落安排立绘切换与声道摆位；`visual.bind_beat` 把立绘缩放、频谱和粒子强度绑定到节拍；`subtitle.style` 设定歌词、译文、IPA 三行的字体、位置和显现方式。全部是图层参数与关键帧，结果在预览里立即可见，可逐项撤销。背景或立绘图片的生成不属于本产品的工具范围，由用户用外部工具准备后作为素材导入。

## 5. 黑客松 MVP 拆解与赛后路线图

### 5.1 核心闭环（路线 B 双层闭环）

一句话：**从一条知乎发音/声乐问答进来，在首屏用双声道动画与连续滑块搞懂差异、导出一张可贴回知乎的发音对比卡；点开底层工作台，同一条歌词与简谱还能在 TextGrid 四轨时间轴上踩着拍子唱歌，每一步都能看、能改、能用说话的方式调用 AI 调音并一步撤销。**

选这个闭环的理由：

- **首屏一眼切中知乎赛道 01**：拿“造成汉语‘算’和英语‘swan’听感差异的是什么？”等真实知乎问答作入口，让文字解释变成可拖动的声道对照与卡片回流。
- **底层壁垒完整不可替代**：保留物理声道在唱歌（看得见）、辅音抢拍与 qTA（听得出差别）、AI 通过工具改参数（改得动且可撤销）三大独有亮点。
- **工程可行且降级稳妥**：不依赖高风险的实时现场反演和腔内气流显示，所有精选案例与回放链路自带预热兜底。

不能砍的只有四样：首屏「算 vs swan」等知乎案例的双声道滑块对比与卡片导出、底层抢拍开关听感对比、AI 提案预览与撤销、以及提前过审的公网可体验链接。

**演示视频**建议控制在 3 分钟以内，直接按 5.2 倒转节奏录屏：前 45 秒展示“造成汉语‘算’和英语‘swan’听感差异的是什么？”原答、拖动双声道过渡滑块并导出对比卡；随后 1 分 45 秒展示切入工作台的抢拍开关、拖动舌尖、AI 改气声提案与撤销；最后 30 秒播放带刘看山立绘的演唱短片。

### 5.5 MVP 验收标准

- **首屏闭环**：首页打开即播（预热缓存零阻塞），能搜索知乎问答、切换多条回答摘要、拖动 0–100% 过渡滑块实时改声道，并导出含学术脚注与缺字校验通过的单音/双音对比卡片。
- **踩拍**：演示乐句中，实测元音起点与拍点的偏差中位数不超过 15 ms，最大不超过 30 ms；关闭抢拍时偏差明显更大（用于对照展示）。
- **基频**：相邻控制帧之间没有超过 0.5 半音的跳变（清音与静音除外）；持音段实测 F0 与音符音高的偏差不超过 20 音分（flutter 调到 0 时测）。
- **撤销**：任意一条命令或一个 AI 提案撤销后，工程文件与撤销前逐字节一致。
- **确定性**：同一工程连续两次渲染，音频哈希相同。
- **AI 与保底**：演示指令连续执行稳定给出通过校验的提案；断网或触发 `30001` 限流时，首屏 5 个精选案例与全流程演示可通过回放完整走完。

### 6.4 测试与可复现

- 调度器、qTA、重定时都是纯函数，适合做快照测试。直接采用原规划里的例子作为第一批用例：120 BPM 下两个韵核落在第 4,800 与第 28,800 个采样。
- 沿用原项目的做法：同一工程两次独立渲染比较音频哈希，导出视频抽帧与预览比较。
- 每次导出都生成一张“可复现卡片”：工程摘要、引擎与几何版本、截面数、种子、说话人、导出参数。科研用户可以直接贴进论文的方法部分。
- 踩拍精度做成一项自动测量：每次构建后合成一组标准音节，报告各类字头的实测偏差。

### 6.5 科研可信度

原项目有一条贯穿始终的原则值得保留，它也是产品在学术用户中立足的基础：模型算出来的量和测出来的量分开说。具体到本产品：控制基频不叫实测基频；模型传递函数的共振不叫输出音频的共振峰；反演结果不叫真实舌位；可视化插值帧不叫合成帧。这些说明放在图例和导出文件的元数据里，不放在用户看不到的文档里。

### 6.6 其他建议

- **方言包做成可署名、可分享的单文件**。包内含转写表、调类表与变调规则（格式见 3.2.6）、个人构型、参考录音，以及作者、方言点、发音人与样本数、许可声明和版本。参考录音是否随包分发由作者决定。知乎上的方言爱好者是很现实的首批用户，包格式定得好，社区内容会自己长出来。
- **教学用途值得单独做一个入口**。“点音标、看构型、听声音、拖一下舌头再听”这条路径对语音学课堂很有用，而且用到的全是现有能力。
- **内置一个完整的示例工程**。新用户打开就能播放、能改、能导出，比任何教程都直接，同时它也是回归测试的整片用例。曲目用自己拥有权利或已进入公有领域的作品；《人是猫》翻唱可以留作内部回归用例，不随安装包分发。
- **AI 提案默认小步**。让模型一次只改一个问题并给出测量对比，比一次改十处更容易让用户建立信任，也更容易定位改坏的地方。
- **不要急着做实时**。这个产品的价值在离线精修与出片，实时演奏是 Chimera 的方向。资源有限时，把“改一处、几秒内听到结果”做好比追求真正的实时更划算。

### 7.6 动手前要先验证的未知项

每项限时半天。结果写进开发日志，结论会影响后面的做法。

1. **Web Wasm 重建与视频封装验证（决定交付路线）**：用 Emscripten 4.0.9 重跑原项目 `scripts/build_m10_wasm.py` 生成 468 KB `vocal-runtime.zip` 与 GPL 源码包；核实浏览器端 WebCodecs 导出 WebM 与前端 `mp4-muxer` 导出 MP4 的实测耗时与兼容性；验证单 Worker 串行预渲染双声部时的内存占用（实测单 Worker 线性内存约 275 MiB）。
2. **（已核实，转为 WP0 明确任务）201 点上限归属**：已查明位于原项目 `trajectory.py` 的 `validate_pitch_curve` / `validate_pressure_curve`，原生 VTL API 按 2.5 ms 步长逐帧输入并无上限。WP0 直接在引擎适配层增加密集 `f0_hz[]` / `pressure_pa[]` 通道即可。
3. 原项目的文本转 IPA 代码能否不经改动在 Node 下运行。这决定赛后无界面出片的做法。
4. 把 `singing.py::compile_song` 的预算与纯 `stop_timing` 时长规则迁到 TS 并改为“相邻韵核之间”后，原有的歌唱测试哪些会变。
5. 原项目的双声部剪辑页能否轻量裁剪承载 4 条核心联动轨，还是按其数据模型重写核心视图更快。同时请负责人确认沿用它是否符合参赛口径（见 1.4.2）。
6. `zhihu-cli` Skill 在当前开发工具里能否安装使用，直答与搜索接口的请求格式、返回结构、每日额度；以及知乎回答/想法对 MP4、WebM、GIF 的上传格式和大小限制。
7. 若走桌面备选路线：精简后的安装包体积，以及在干净机器上的首次启动时间。

### 7.7 工作方式

- **先计划后编码。** 接到工作包后先给出实现计划（要读哪些原文件、要建哪些新文件、接口、测试），负责人确认后再写代码。
- **一次只做一个工作包**，改动范围不超出它。顺手发现的其他问题写进汇报，不要顺手改。
- **测试与代码一起提交。** 验收一栏写的测试是完成的定义。
- **留下开发日志。** 赛事规则建议留存 AI 交互记录、设计底稿和开发日志。每个工作包在 `docs/devlog/` 下留一份记录：日期、使用的工具与模型、任务、关键决策、沿用了哪些已有代码。
- **汇报格式固定为四段**：做了什么；没做什么以及原因；验证了什么以及怎么验证的；没有验证的部分和已知问题。
- **不要把演示效果当作验收。** “看起来能跑”不算完成，以 7.5 的验收项和 5.5 的 MVP 标准为准。

### B. 术语

| 术语 | 含义 |
| --- | --- |
| VTL | VocalTractLab，Peter Birkholz 开发的发音合成器，本产品的声学引擎 |
| 构型、姿态 | 某一时刻全部声道参数的取值，决定声道形状 |
| 面积函数 | 从声门到唇，声道各处的横截面积 |
| qTA | 定量靶点逼近模型：基频以三阶临界阻尼系统逐音节逼近一条直线靶点 |
| PENTA | 并行编码与靶点逼近框架：声调、焦点、句类等功能并行地修饰靶点 |
| 五度值 | 赵元任五度标调法，1 最低、5 最高 |
| 调类 | 一个方言里声调的类别（阴平、阳平等）。调类是标签，调值是它的实际音高 |
| 连读变调 | 音节连读时声调按规则发生的变化 |
| 入声 | 以塞音或喉塞音收尾、时长短促的调类 |
| 发音卡片 | 把一个音或词导出成带声道动画、IPA 和合成音的短视频，见 2.9 |
| 靶点 `(m, b, λ)` | 斜率、高度、逼近速率 |
| 韵核 | 音节里承载音高与时值的主元音 |
| 前导量 | 字头辅音抢在拍点之前占用的时长 |
| VOT | 嗓音起始时间：塞音除阻到声带开始振动的间隔 |
| P-center | 节拍感知中心：听感上一个音节“落在拍上”的时刻 |
| TextGrid | Praat 的分层时间标注格式 |
| 连续统 | 在两个端点刺激之间等步过渡的一组合成刺激，用于感知实验 |
| 反演 | 从录音估计声道构型序列；结果是模型的候选解释，不是实测舌位 |
| 提案 | AI 的一组修改，先在副本上预演，用户接受后才合并，整体作为一步撤销 |
