# VocalCut Studio 代码审阅报告

审阅日期为 2026 年 11 月 25 日。对象为当前工作目录中的源码和本机构建依赖。科研工作流优先，覆盖方言采录、声道连续统、Praat 标注交换、声道重建、VTL 合成、模型技术报告、调音台和舞台预览。代码位置按本次工作区快照记录。

## 结论

**最先需要处理的是会静默改变实验数据的问题。** 单字调值拟合丢失说话人调域信息，连续统导出的参数表会把擦音标作元音，并把 16 kHz 音频列为 48 kHz。VTL 接口对于部分合法控制帧率也会返回时间基准错误的轨迹。上述结果均有可重复的输入输出对照。

**资源与交互方面，优先处理方言录音和舞台视频。** 在麦克风授权返回之前切页，录音器会在原页面卸载后启动。播放中进入新视频片段时，视频时钟可以继续走，监视器却停留在同一幅画面。两项都已在 Edge 中复现。

下文的 P1 表示会改变科研交付、妨碍主要功能或让采集脱离用户控制。P2 表示有明确触发条件的正确性、性能或布局问题。每项分别注明实际验证深度。

## 一、事实与科学性

### S1 · P1　单字 F0 拟合会把不同音高的平调都写成 11

方言包以**当前这一个录音**的最低 F0 为一级，用该录音的极差与 40 Hz 中的较大值作分母，再将起、中、末三个点换成五度值。当曲线完全平坦，三个点减去最低值都得到零。浏览器测试固定 SwiftF0 接口分别返回 25 帧 120 Hz、25 帧 240 Hz，经「载入本地音频」导入单字，两次页面都显示「拟合调值 11」。原始 Hz 曲线有保留，但当前调类的 `pts` 和 `chao` 已被自动覆盖，保存方言包时会保留这个结果。

建议将单字 F0 曲线与调类定义分开保存，用同一说话人的参考调域换算五度值。没有调域时可先保留 Hz 和原有调类。验收时至少比较同一调域内的高、低平调，以及整体移高但形状相同的两条曲线。[单字自动拟合、调类回写与保存，L157、483–487、520–533](../../src/components/research/DialectStudioView.vue)

### S2 · P1　物理合成返回的 50 Hz 轨迹有时只有 25 帧，有时达到 63 帧

通过本次工作区启动的临时 HTTP 引擎，向 `/vtl/synthesize` 提交固定构型、165 Hz、650 Pa、时长 1 秒的输入，并请求 `return_control_track`。实际返回如下。

| 输入控制帧率 | 音频时长 | 标为 50 Hz 的轨迹 | HTTP |
| --- | --- | --- | --- |
| 25 Hz | 1.000 s | 25 帧 | 200 |
| 125 Hz | 1.000 s | 63 帧 | 200 |
| 200 Hz | 1.000 s | 50 帧 | 200 |
| 省略帧率，按默认 200 Hz 给 200 帧 | 响应未交付 | 无，取缺失的 `frame_step_ms` 触发异常 | 500 |

引擎接受这些显式帧率，响应层却用整数步长 `step_hz // 50` 抽取。下游若按 20 ms 一帧解释 63 帧，时间轴会延伸到 1.26 秒。流式响应中也有相同抽取逻辑，本次实调的是非流式路由。建议两条路由共享输入帧率解析，并在目标 50 Hz 的帧心采样。验收应同时检查帧数和带时间标记的构型变化位置。[HTTP 响应组装，L757–764](../../engine/server.py) · [合法帧率、默认值与流式轨迹，L714–722、1472–1477](../../engine/dense_channel.py)

### S3 · P1　连续统的实验参数 JSON 与交付的刺激不一致

两次独立浏览器操作得到下列结果。

| 操作 | 清单内容 | 导出实物或所选条件 |
| --- | --- | --- |
| 端点 A 选内置平舌擦音 [s]，导出参数 | 第 1 格为 `ipa=s, manner=vowel, articulator=vowel, role=nucleus, t_ms=140` | 所选端点是擦音。140 ms 来自固定常量 |
| 选择神经合成，导出参数并下载第 1 格音频 | `sample_rate_hz=48000`，文件名为 `vc_continuum_5_a01of05_b01of01.wav` | 实际文件为 `连续统-1-1.wav`，WAV 头为 **16,000 Hz、10,560 样点** |

两个端点均被写成元音核，另一个端点的标志时间固定为 165 ms。导出继续沿用通用清单的工程采样率和命名规则。按清单文件名批量配对会失败，按清单采样率解释这份音频的样点数会得到 0.22 秒，WAV 实际为 0.66 秒。建议从同一格的最终渲染结果生成音频元数据和文件名，将工程时间基准单列。没有标注的构型应省去未经测定的标志时间。[端点分类、下载和清单导出，L466–500、798–802、866–867、943–960](../../src/components/research/ContinuumView.vue) · [通用清单采样率，L301–305](../../packages/core-ts/src/continuum.ts)

### S4 · P1　神经连续统在中点额外切换参考声纹

当 A、B 均为音频端点，合成请求在 `α < 0.5` 时发送 A 的参考录音，在 `α ≥ 0.5` 时发送 B 的参考录音。由此，同一行的 0.49 格和 0.50 格除了预定的声道变化，还更换了声码器的说话人条件。两端来自不同说话人时，感知实验无法仅凭这组刺激把中点附近的反应变化归因于声道插值。

已核对前端请求与引擎声纹入口，未做听辨，也未估计效应量。建议让整条连续统复用明确选定的参考声纹，将其来源写入清单。验收可直接比较各格参考音频的标识或摘要。[参考录音选择与请求，L789–794](../../src/components/research/ContinuumView.vue) · [声纹参与神经重合成，L1200–1228](../../engine/m27_bridge.py)

### S5 · P1　连续统显示的传递函数峰与物理合成使用的构型可能不同

界面已插值唇宽、喉高、舌形、唇形和手动舌根开关。批量求轮廓、F1–F3 和最小截面积时只提交 19 个主参数，底层用唇宽 1、喉高 0 并重置形状。实际物理合成又传入了插值后的唇宽与喉高，遗漏了已计算的舌形、唇形和手动舌根。实验参数表里的峰值取自前一条路径。

原生 JD2 对照中，固定同一中性构型与喉高，只把唇宽从 1.0 改为 1.3，F1/F2 就从 **503.9/1230.5 Hz** 变为 **515.6/1242.2 Hz**。这验证了遗漏的参数确实能影响读数。这里比较的都是 VTL 传递函数峰。建议预览、参数导出和物理合成共用同一份完整构型，并用非默认唇宽复查三条路径。[界面插值、测量与合成，L354–371、606–612、807–814](../../src/components/research/ContinuumView.vue) · [批量轮廓，L1915–1943](../../engine/dense_channel.py) · [原生构型与传递函数，L446–455、476–483](../../engine/vtl_native/phonetic_core/vocal_tract/engine.py)

### S6 · P1　科研导出的 TextGrid 在停顿处断层，多片段还可能在同层重叠

用工程导出函数实测，给定两个时段 0–0.3 秒、0.6–1.0 秒，得到的 `phone` 层仅含这两段，0.3–0.6 秒没有空标签区间。导出函数把所有片段的音节和音素直接追加到各自的同一层。对时间重叠的两个片段，该路径也没有拆层或报告冲突。Praat 要求同一 IntervalTier 内的相邻区间首尾相接；违反这一条件的文件有被拒读或被修复的可能，具体取决于读取器。

建议按所选片段或轨道组织层，在停顿处补空标签区间，并在导出前检查覆盖范围和重叠。引擎中的对齐 TextGrid 已有补空区间的实现可供参考。[科研导出入口，L65](../../src/components/modals/ExportModal.vue) · [工程转 TextGrid，L185–222](../../packages/core-ts/src/textgrid.ts) · [引擎已有补空逻辑，L483–499](../../engine/onnx_inference.py) · [Praat 官方格式说明第 6 节](https://praat.org/manual/TextGrid_file_formats.html)

### S7 · P2　TextGrid 导入会拒绝标准短格式，也会把残缺长格式当作成功

按 Praat 标准短格式构造一个 0–1 秒的 `phone` 层，含一个标为 [a] 的区间。浏览器中的项目解析器返回「TextGrid 头部数值无效」。原因是代码只跳过以 `tiers?` 开头的行，把短格式独立成行的 `<exists>` 当作层数。反方向的试验中，保留长格式头部声明的三层，截到第一层末尾，解析器却返回 `ok: true` 和一层数据。文件读取入口只要求存在非空标注，无法发现后两层缺失。

建议支持短格式独立标记，同时校验声明数量和实读数量。回归用例应包括 Praat 生成的长、短格式，以及在完整层后截断的文件。[解析循环和成功出口，L73–125](../../packages/core-ts/src/textgrid.ts) · [文件读取入口，L4–14](../../src/data/textgrid-alignment.ts) · [Praat 官方短格式示例](https://praat.org/manual/TextGrid_file_formats.html)

### S8 · P2　普通话盲对齐中的轻声 de、me 会保留一声模板的元音

盲对齐先用固定的 `tone=1` 将拼音展开为音素并进行对齐，随后才从声调头判定声调、更新音节标签。音素序列未随判定结果更新。直接调用项目自己的转换器，`de` 在一声与轻声条件下分别返回 [t, ɤ] 和 [t, ə]，`me` 分别返回 [m, ɤ] 和 [m, ə]。因此即使声调头选中了轻声，音素层仍可与本项目的轻声转写规则矛盾。

此项已核对转换输出和解码顺序，未测自然录音中该现象的出现率。建议让最终音节标签、音素候选及时间对齐使用一致的声调条件。[盲解码与后置声调判定，L1106–1149](../../engine/onnx_inference.py) · [项目轻声规则，L184–198](../../engine/model_bundle/src/tt3/mandarin_unt_ipa.py)

### S9 · P2　技术报告混淆了面积模型输出和声道截面数

`Tract2Area-Proxy` 的模型说明写作「65 截面声道面积函数快速代理」。实际 ONNX 输出的末维是 **6**，依次为全口腔及唇、舌冠、舌背、咽部的最小面积，以及鼻咽口面积。六个汇总量无法还原沿声道排列的 65 点面积函数。建议在模型表中列明这六个量，并把截面数放回原生几何说明。[面向用户的模型说明，L102–110](../../src/data/model-training-report.ts) · [运行时输出形状，L232–245](../../engine/model_registry_runtime.py) · [训练目标定义，L23–39](../../engine/model_bundle/src/tt3/kf_models.py)

### S10 · P2　技术报告中的 CPU 延迟缺少与数字相符的测量条件

图 1 将 Vox2Tract-Lite 的 **80.2 ms、RTF 0.0289** 归入纯 ONNX 单句实测。可追溯到的原始训练摘要将同一对数值列在 `eval_8clips` 的均值中；计时代码用 PyTorch 调用 `stu_fp16(...)`，再求八段录音的均值。仓库的 ONNX 导出脚本另外计量 PyTorch 和 ORT 耗时。当前数字直接支持的是训练端的八段平均，尚缺支撑图注所述 ONNX 单句条件的测量记录。

## 三、排版与布局

**L1 · P2　同样为 16:10 的桌面窗口，缩小时不满足完整显示约定。** 在固定模拟屏幕 2560×1600、DPR 1、自动页面缩放为 100% 的条件下，将可用窗口设为 1120×700。公开版和参赛版的调音台都得到 **1260×720** 的应用外壳。公开版右侧「帮助与关于」「AI 助手」按钮起点已在可视区之外，需要滚动外壳才能操作。根因是最低宽高按整块屏幕及缩放系数计算，覆盖了当前窗口的可用宽高。同一屏幕上 1440×900 的公开版可完整容纳外壳，2560×1600 基准也通过了几何检查。

建议用可用窗口尺寸决定最低外壳或页面缩放，保留面板内部按需滚动。回归时应固定显示器尺寸、单独改变窗口大小；如果模拟测试把屏幕也跟着缩小，自动缩放会掩盖问题。[外壳计算，L32–50](../../src/App.vue) · [按屏幕选择自动缩放，L217–225](../../src/styles/skin-registry.ts) · [根容器滚动，L1–3](../../src/styles/workstation.css)
