# VoxFigura 新版编曲与剪辑联动方案

2026-11-26 · 修订评估稿。新版工程独立设计，保留现有模块向编曲传送音频、TextGrid 和重建信息的能力。此稿取代先前按声部维护两种编辑源的方案。

## 1. 编曲数据

MIDI 导入、手绘、逐字简谱输入共用一份音符数据。每音有稳定 ID、所属轨、MIDI 音高、力度和 48 kHz 整数采样起止，区间采用半开形式。全曲保存速度及拍号表，按文件 PPQ 分段换算音符两端，吸附仅用于主动编辑。Format 0 按通道提供分组选项，Format 1 保留原轨并显示通道，多选一次提交。第一版优先支持 PPQ 的 Format 0/1，其他时间基准或格式在导入预览中说明。保存音符、选用的音色、源轨身份和可用的歌词事件。弯音、踏板及未映射乐器的回放能力在预览中列明。

器乐轨允许同轨和弦、交叠及各音独立释放。卷帘支持在空轨画音、横移、移调、伸缩、多选、复制和删除。人声用一条单音旋律绑定歌词，复调 MIDI 可选取其中一条旋律复制给人声。按音节 ID 关联一个或多个音符，保留 IPA 和音素分界。没有歌词的器乐轨可以直接试听。单音旋律越过 60–600 Hz 或出现重叠时定位问题音符，原器乐数据仍可编辑。

逐字简谱是声乐旋律的输入和显示方式。对选中音节应用简谱时，解析成对该组音符的一次修改，保留无关音符的时值、力度及绑定。一个字唱两个音可以显示为括号连音。复调和弦在卷帘编辑，复杂实录节奏的简谱近似显示不能反写原始端点。旧工程读取与迁移不列为验收条件。新版文件采用新格式标识，另存新文件，旧工程原件自持。

## 2. 音频与 TextGrid 进入编曲

目前标注、声道重建、混音和剪辑经共享工作区传送对象发送素材。载荷已有文件、可选解码音频、TextGrid、乐句、重建参数帧和来源信息。入口保留，新增适配器把一次传送转换为工程内素材，再打开相应编曲视图。当前待接收对象仅存在内存中，应在接收成功后持久化项目引用和必要素材。 [跨模块传送](../../src/data/workspace-transfer.ts) · [编曲接收](../../src/components/studio/StudioArrangerView.vue#L310)

| 输入 | 新版行为 |
| --- | --- |
| 仅音频 | 建立原音参考轨，可播放、对时和叠加 MIDI。推算旋律由用户单独触发 |
| 音频和 TextGrid | 绑定同一素材。保留原层名、时间域、区间、空段及点标注数据，选择适用的音节层与音素层生成工作视图 |
| 单独 TextGrid | 保存为待关联的标注素材，可关联已有录音。没有可靠来源时显示候选音频及范围，不猜绑定 |
| 原音、标注和重建信息 | 同时保留原声、标注及可用的动态咬字、F0、源片段偏移，使改调演唱与原录音可对照 |

用解码帧数、实际采样率和源截取区间确定音频边界，统一换算到 48 kHz。当前仅收音频和 TextGrid、缺少 Clip 与重建帧时，接收端用一秒作为估计，合法的长标注可能被拒绝。新版应先取得真实音频长度。TextGrid 的原始时间和为新旋律计算的演唱时间分别保存；移动音符后只重算演唱。已有 Clip 和 TextGrid 同时到达时保留两者，显示采用哪份作为工作标注。 [区间校验](../../src/data/textgrid-alignment.ts)

## 3. 从编曲进入剪辑

引入可回编的编曲素材。编曲工程持有素材 ID、各声部 ID、修订号和统一音乐零点；舞台实例持有素材及声部引用、采用的修订、时间线位置、源入点、裁切长度和混音设置。可编辑乐谱、原始录音和标注随工程可恢复。渲染音频作为缓存，以源修订、音色、模型设置和渲染参数识别；重建演唱所需的原始输入须持久化或明确要求重新关联。

1. 用户点击「发送到剪辑」，勾选声部和插入位置。默认生成同一组内可单独混音的片段。例如主唱、钢琴、贝斯分别入轨，共用音乐零点。主唱携带歌词、音素和已有的声道动画；器乐轨携带各自的声音。
2. 剪辑页默认折叠组，展开可单独静音、独听、调增益或裁切。音频轨增加显式用途和稳定 ID，去除用 A3 判断伴奏、其余轨一律按人声处理的依赖。现有 A1–A12 判定、轨道创建、碰撞、菜单和导出一起核对。批量放置先检查整组，冲突时选新轨或新位置，一次撤销整个操作。
3. 双击「回编曲」定位到源声部，并标出当前剪辑使用的源区间。普通拖动、分割和裁切只改实例。编曲修改后显示可更新，明确选择更新哪些使用实例。保留各实例的入点、时间线位置、音量包络和字幕/声道关联。源缩短导致入点越界时给出修剪或保留旧版的选择。
4. 首期建议采用显式更新。已经送到剪辑的修订应保留可重新渲染的数据，或保存冻结音频及必要的动画、字幕，直到引用它的片段释放。先准备各分轨结果，再一次替换所选实例，失败时仍可播放上一版。多个实例使用同一源时可以复用缓存。
5. 剪辑继续共用现有音频准备与调度路径。加入编曲引用解析后，把各声部转换为带源偏移的音频，再使用已有预览和视频导出。约定缓冲区零点、辅音前导、器乐释放尾音和字幕起点，按样本核对裁切、跳播与导出。在剪辑媒体库导入 MIDI 也走同一导入器，生成可打开编曲的素材。

目前发送函数按当前声部渲染，传送对象只有一个可选伴奏。舞台已有乐句、V1 声道、V3 字幕和增益包络。舞台播放与 MP4/WebM 导出共享音频调度，适合在此复用已有能力。 [编曲发送](../../src/components/studio/StudioArrangerView.vue#L1894) · [剪辑接收](../../src/components/studio/StudioStageView.vue#L695) · [轨道模型](../../src/components/studio/nle-timeline.ts) · [舞台音频](../../src/components/studio/stage-audio.ts#L248)

## 4. Tauri 2 体积与运行资源

现有脚本重新构建各版本 Vite 产物，组入应用目录，再将 LZMA2 归档、7zr 和 Tauri 2 启动壳拼为交付 EXE。MIDI 文件解析可在前端按需加载，用现有乐器和人声引擎回放。无需随此功能引入通用 SoundFont、原生 MIDI 服务或新模型。 [组包脚本](../../scripts/portable/build.py#L270)

实测候选 midi-file 1.2.4 的 npm 发布包，并核对 SHA-512。它没有运行依赖；读文件的 JS 源码为 9,650 字节，单独用 32 MiB 字典的 LZMA2 压缩为 2,081 字节。这个数仅覆盖解析器。最终测量应对比同版本、同资源、同打包参数的前后两份 EXE、逐文件清单及首次展开目录，单列新增界面、编辑器、Worker 和许可证。 [候选库](https://github.com/carter-thaxton/midi-file)

用户音频、导入的 MIDI、TextGrid 和分轨渲染属于工程或运行缓存。48 kHz、16-bit、立体声 PCM 每分钟约 11.52 MB；8 条三分钟满长分轨约 276.48 MB，内存 Float32 解码缓冲约为对应 PCM16 的两倍。分轨按需渲染，长片段分段读取，缓存设可清理容量；清理时保留工程恢复所需的原始素材和已冻结修订。另行引入大型音色库时独立评估体积和许可。

## 5. 实施优先级与验收

1. 先做贯穿两个页面的样例：一条 MIDI 钢琴和弦、一条贝斯和一条带 TextGrid 的主唱参考录音。导入、绑定、分轨送剪辑、裁切、保存并关闭，清空会话内存后重开，确认三个声部均可播放且可以回编。
2. 接通正式 MIDI 导入、逐字简谱写入、歌词与 IPA 绑定、卷帘手绘、撤销和跨变速处理。用同轨三音不同结束、重叠音、文件起始空拍及三连音核对保存前后的样本端点。
3. 扩展剪辑轨道用途、编曲素材和批量更新。测试同一源被引用两次、已裁切实例只更新其中一个、源缩短、重渲染取消及缺失外部原音时的恢复。测试标注、声道重建、混音及剪辑四类实际传送入口。
4. 在浏览器和 Tauri 2 WebView2 分别验证试听、MP4/WebM 实际解码、增益及静音、声道和字幕同步。覆盖三版本构建，按项目打包规范对实际目标产物做首启、离线及体积对比。以跨模块闭环、工程重开和成片结果作为验收依据。
